## 📌 1. IPv4 vs IPv6 (Διευθύνσεις Δικτύου)

Κάθε συσκευή που συνδέεται σε ένα δίκτυο IP πρέπει να διαθέτει μια μοναδική διεύθυνση (Logical Address) για την αναγνώρισή της και τη δρομολόγηση των πακέτων.

### IPv4 (Internet Protocol version 4)
* **Αρχιτεκτονική:** Αποτελείται από 32 bits, χωρισμένα σε 4 οκτάδες (8-bit fields) που χωρίζονται με τελείες (Dotted Decimal Notation, π.χ. `192.168.1.1`).
* **Το Πρόβλημα (IPv4 Exhaustion):** Το μέγιστο πλήθος διευθύνσεων είναι $2^{32}$ (περίπου 4.3 δισεκατομμύρια). Λόγω της έκρηξης των συσκευών (IoT, Smartphones), οι διευθύνσεις αυτές έχουν εξαντληθεί παγκοσμίως.
* **Μηχανισμός Διάσωσης (Private vs Public):** Για την επιβράδυνση της εξάντλησης, οι διευθύνσεις χωρίστηκαν σε:
  * **Private IPs:** Χρησιμοποιούνται αποκλειστικά εντός του τοπικού δικτύου (LAN). Δεν είναι δρομολογήσιμες (non-routable) στο δημόσιο Internet και επαναχρησιμοποιούνται σε κάθε σπίτι/εταιρεία.
    * *Class A:* `10.0.0.0` έως `10.255.255.255`
    * *Class B:* `172.16.0.0` έως `172.31.255.255`
    * *Class C:* `192.168.0.0` έως `192.168.255.255`
  * **Public IPs:** Μοναδικές παγκοσμίως, αγοράζονται/εκχωρούνται από τους παρόχους (ISPs) και επιτρέπουν την απευθείας επικοινωνία με το Internet.
* **Loopback Address:** Η διεύθυνση `127.0.0.1` χρησιμοποιείται για local testing της κάρτας δικτύου της ίδιας της συσκευής (localhost).

### IPv6 (Internet Protocol version 6)
* **Αρχιτεκτονική:** Αποτελείται από 128 bits, γραμμένα σε δεκαεξαδική μορφή (Hexadecimal) και χωρισμένα σε 8 ομάδες των 16 bits (hextets) με άνω-κάτω τελείες (π.χ. `2001:0db8:85a3:0000:0000:8a2e:0370:7334`).
* **Χωρητικότητα:** Παρέχει $2^{128}$ διευθύνσεις (περίπου $340$ ενδεκάκις εκατομμύρια), ένας αριθμός πρακτικά άπειρος, εξαλείφοντας πλήρως την ανάγκη για NAT και Private/Public διαχωρισμό.
* **Τύποι Μετάδοσης (Cast Types):** * *Unicast:* One-to-one επικοινωνία.
  * *Multicast:* One-to-many επικοινωνία (αντικαθιστά το Broadcast του IPv4).
  * *Anycast:* One-to-closest επικοινωνία (το πακέτο παραδίδεται στον πλησιέστερο router που διαθέτει αυτή τη διεύθυνση).
* **SLAAC (Stateless Address Autoconfiguration):** Επιτρέπει σε μια συσκευή να δημιουργήσει μόνη της μια έγκυρη, παγκόσμια IPv6 διεύθυνση χρησιμοποιώντας το prefix του router και τη δική της MAC address (μέσω της μεθόδου EUI-64), χωρίς την ανάγκη DHCP server.

## 📐 2. Subnetting & CIDR (Υποδικτύωση)

* **Ορισμός:** Η διαδικασία του μαθηματικού διαχωρισμού ενός ενιαίου φυσικού δικτύου σε δύο ή περισσότερα μικρότερα, αυτόνομα λογικά υποδίκτυα (subnets).
* **Σκοπός και Αναγκαιότητα:**
  1. **Ασφάλεια (Security):** Απομόνωση τμημάτων (π.χ. το δίκτυο της Οικονομικής Διεύθυνσης δεν πρέπει να επικοινωνεί απευθείας με το δίκτυο των επισκεπτών Wi-Fi).
  2. **Περιορισμός του Broadcast Domain:** Κάθε broadcast μήνυμα σταματάει στα όρια του υποδικτύου, μειώνοντας το συνολικό network congestion (κίνηση) και αυξάνοντας την απόδοση.
* **Subnet Mask (Μάσκα Υποδικτύου):** Μια ακολουθία 32 bits (άσσοι και μηδενικά). Οι άσσοι (`1`) ορίζουν το Network ID (το αναγνωριστικό του δικτύου) και τα μηδενικά (`0`) ορίζουν το Host ID (τις διευθύνσεις των συσκευών).
  * *Παράδειγμα:* Μάσκα `255.255.255.0` σημαίνει δυαδικά 24 άσσοι και 8 μηδενικά.
* **CIDR (Classless Inter-Domain Routing):** Αντικατέστησε το παλιό, δύσκαμπτο σύστημα των κλάσεων (Class A, B, C). Εκφράζεται με το σύμβολο `/` ακολουθούμενο από τον αριθμό των bits δικτύου (π.χ. το `192.168.1.0 255.255.255.0` γράφεται ως `192.168.1.0/24`).
* **Βασικοί Μαθηματικοί Τύποι:**
  * Αριθμός Υποδικτύων = $2^n$ (όπου $n$ τα bits που "δανειστήκαμε" από το host portion).
  * Αριθμός Hosts ανά Υποδίκτυο = $2^h - 2$ (όπου $h$ τα εναπομείναντα bits των hosts). Αφαιρούμε πάντα 2 διευθύνσεις: την πρώτη που είναι το **Network Address** (Διεύθυνση Δικτύου) και την τελευταία που είναι το **Broadcast Address** (Διεύθυνση Εκπομπής).
* **VLSM (Variable Length Subnet Masking):** Η τεχνική σχεδιασμού όπου χρησιμοποιούνται διαφορετικές μάσκες υποδικτύου (π.χ. `/26`, `/28`, `/30`) στο ίδιο μεγάλο δίκτυο, ώστε να δίνεται σε κάθε τμήμα ακριβώς ο αριθμός των IPs που χρειάζεται, εκμηδενίζοντας τη σπατάλη.

## 🏷️ 3. DNS (Domain Name System)

* **Ορισμός:** Το DNS λειτουργεί ως ο "τηλεφωνικός κατάλογος" του Internet, μετατρέποντας τα αλφαριθμητικά ονόματα (Hostnames) που θυμούνται οι άνθρωποι σε αριθμητικές διευθύνσεις IP που καταλαβαίνουν οι μηχανές.
* **Η Διαδικασία Ανάλυσης (DNS Resolution Process):**
  Όταν πληκτρολογείς `google.com` στον browser, εκτελούνται 4 βήματα:
  1. **DNS Recursor (Resolver):** Ο server του παρόχου σου ή δημόσιων υπηρεσιών (π.χ. `1.1.1.1` της Cloudflare, `8.8.8.8` της Google). Λαμβάνει το αίτημα και ψάχνει την απάντηση.
  2. **Root Nameservers (`.`):** Το πρώτο βήμα στην ιεραρχία. Δεν ξέρει την IP, αλλά κατευθύνει τον Resolver στον σωστό TLD Server βάσει της κατάληξης.
  3. **TLD Nameservers (Top-Level Domain):** Διαχειρίζεται τις καταλήξεις (π.χ. `.com`, `.gr`, `.org`). Κατευθύνει τον Resolver στον Authoritative Server του συγκεκριμένου domain.
  4. **Authoritative Nameservers:** Ο τελικός διακομιστής που κρατάει τα επίσημα αρχεία (DNS Records) του site. Επιστρέφει την IP στον Resolver και αυτός στον browser.

### Κύριοι Τύποι DNS Records:
* **A Record:** Αντιστοιχίζει ένα Hostname σε μια διεύθυνση IPv4.
* **AAAA Record:** Αντιστοιχίζει ένα Hostname σε μια διεύθυνση IPv6.
* **CNAME (Canonical Name):** Δημιουργεί ψευδώνυμα (alias). Δείχνει ένα όνομα σε ένα άλλο όνομα (π.χ. το `www.site.com` δείχνει στο `site.com`).
* **MX Record (Mail Exchanger):** Ορίζει τους mail servers που είναι υπεύθυνοι για τη λήψη των email του συγκεκριμένου domain.
* **TXT Record:** Επιτρέπει την εγγραφή κειμένου, απαραίτητο για επαλήθευση ιδιοκτησίας και ασφάλεια email (SPF, DKIM, DMARC).

* **Διαγνωστικά Εργαλεία:** `nslookup google.com` ή η πιο αναλυτική εντολή `dig google.com` για Unix συστήματα.

## 🔌 4. DHCP (Dynamic Host Configuration Protocol)

* **Ορισμός:** Ένα πρωτόκολλο Application Layer (Layer 7) που αυτοματοποιεί πλήρως την απόδοση ρυθμίσεων δικτύου στις συσκευές, εξαλείφοντας τη χειροκίνητη παραμετροποίηση (Static IP assignment) και τα IP conflicts.
* **Τι παραχωρεί (Lease):** Ο DHCP server δανείζει στη συσκευή για συγκεκριμένο χρόνο (Lease Time):
  1. **IP Address** (Διεύθυνση IP)
  2. **Subnet Mask** (Μάσκα Υποδικτύου)
  3. **Default Gateway** (Την IP του router για έξοδο από το LAN)
  4. **DNS Servers** (Για την ανάλυση ονομάτων)

### Η Διαδικασία DORA (4-Way Handshake):
1. **Discover (Broadcast):** Η νέα συσκευή εκπέμπει ένα μήνυμα σε όλο το δίκτυο: *"Υπάρχει κάποιος DHCP Server διαθέσιμος;"*
2. **Offer (Unicast/Broadcast):** Ο DHCP Server απαντάει προσφέροντας μια συγκεκριμένη IP και τις παραμέτρους της.
3. **Request (Broadcast):** Η συσκευή απαντάει αποδεχόμενη την προσφορά: *"Κρατήστε μου αυτή την IP, την αποδέχομαι!"* (Γίνεται broadcast ώστε τυχόν άλλοι DHCP servers να αποδεσμεύσουν τις δικές τους προσφορές).
4. **Acknowledge (Unicast/Broadcast):** Ο Server επιβεβαιώνει τη μίσθωση και κλειδώνει την IP για τη συσκευή.

* **APIPA (Automatic Private IP Addressing):** Αν η διαδικασία DORA αποτύχει (π.χ. δεν υπάρχει DHCP Server ή υπάρχει πρόβλημα στο καλώδιο/Wi-Fi), το λειτουργικό σύστημα (Windows/Mac) εκχωρεί μόνο του μια διεύθυνση από το εύρος `169.254.0.1` έως `169.254.255.254`. **Αν δείτε IP 169.254.x.x, σημαίνει 100% πρόβλημα επικοινωνίας στο Layer 2 ή στον DHCP Server!**

## 🔄 5. NAT (Network Address Translation) & PAT

* **Ορισμός:** Η τεχνολογία που επιτρέπει σε έναν router να μεταφράζει τις Private IPs του τοπικού δικτύου σε μία (ή περισσότερες) Public IPs, επιτρέποντας σε χιλιάδες εσωτερικές συσκευές να μοιράζονται μία μόνο σύνδεση Internet.

### Τύποι NAT:
1. **Static NAT (1-to-1):** Μία συγκεκριμένη Private IP αντιστοιχίζεται μόνιμα σε μία Public IP. Χρησιμοποιείται όταν ένας εσωτερικός server (π.ex. Web Server) πρέπει να είναι προσβάσιμος από τον έξω κόσμο.
2. **Dynamic NAT:** Ο router διαθέτει μια δεξαμενή (Pool) από Public IPs και τις εκχωρεί δυναμικά στις εσωτερικές συσκευές όταν αυτές ζητούν πρόσβαση στο Internet.
3. **PAT (Port Address Translation / NAT Overload):** Η πιο διαδεδομένη μορφή (αυτό που τρέχει στα οικιακά και εταιρικά routers). Ο router χρησιμοποιεί **Source Ports** (θύρες προέλευσης) για να ξεχωρίζει ποια συσκευή έστειλε τι.
   * *Πώς λειτουργεί:* Αν το PC-A (`192.168.1.10`) και το PC-B (`192.168.1.20`) ζητήσουν ταυτόχρονα μια σελίδα, ο router στέλνει τα πακέτα με την ίδια Public IP (π.χ. `82.102.1.5`), αλλά αλλάζει τα ports σε `82.102.1.5:50001` για το PC-A και `82.102.1.5:50002` για το PC-B. Όταν έρθουν οι απαντήσεις, ο router κοιτάει το port, ξέρει σε ποιον ανήκει και κάνει τη μετάφραση.

## 📦 6. TCP vs UDP (Επίπεδο Μεταφοράς - Layer 4)

Στο Layer 4, το TCP και το UDP καθορίζουν τον τρόπο πολυπλεξίας, ελέγχου και μεταφοράς των δεδομένων.

| Χαρακτηριστικό | TCP (Transmission Control Protocol) | UDP (User Datagram Protocol) |
| :--- | :--- | :--- |
| **Αξιοπιστία** | 100% Αξιόπιστο. Εγγυάται την παράδοση. Αν χαθεί πακέτο, γίνεται επανεκπομπή (Retransmission). | Best-effort delivery. Μη αξιόπιστο. Αν χαθεί πακέτο, απλά χάθηκε. |
| **Ταχύτητα** | Πιο αργό. Έχει μεγάλο header (20 bytes) και καθυστερεί λόγω ελέγχων. | Ταχύτατο. Μικρό header (8 bytes), στέλνει δεδομένα αμέσως χωρίς ελέγχους. |
| **Σύνδεση** | Connection-oriented. Απαιτεί εγκαθίδρυση σύνδεσης (Handshake) πριν τη μεταφορά. | Connectionless. Στέλνει τα πακέτα (datagrams) τυφλά, χωρίς προειδοποίηση. |
| **Έλεγχος Ροής** | Διαθέτει Flow Control (Windowing) για να μην υπερφορτωθεί ο παραλήπτης. | Δεν διαθέτει κανέναν μηχανισμό ελέγχου ροής ή συμφόρησης. |
| **Use Cases** | Web (HTTP/S), Email (SMTP/IMAP), File Transfer (FTP), SSH. | VoIP, Live Streaming, Online Gaming, DNS queries, DHCP. |

### TCP 3-Way Handshake (Εγκαθίδρυση Σύνδεσης):
Πριν σταλεί οποιοδήποτε δεδομένο μέσω TCP, ο client και ο server συγχρονίζονται χρησιμοποιώντας Flags (σημαίες) στον header:
1. **SYN (Synchronize):** Ο Client στέλνει ένα πακέτο με ένα τυχαίο Sequence Number (π.χ. $X$) ζητώντας σύνδεση.
2. **SYN-ACK (Synchronize-Acknowledge):** Ο Server απαντά επιβεβαιώνοντας τη λήψη ($Acknowledgment Number = X+1$) και στέλνει το δικό του Sequence Number ($Y$).
3. **ACK (Acknowledge):** Ο Client επιβεβαιώνει τη λήψη ($Acknowledgment Number = Y+1$). Η σύνδεση είναι πλέον "Established".

## 🔒 7. HTTP vs HTTPS & TLS (Επίπεδο Εφαρμογής - Layer 7)

* **HTTP (Port 80):** Hypertext Transfer Protocol. Μεταφέρει τα δεδομένα των ιστοσελίδων σε μορφή απλού κειμένου (Plain Text). Οποιοσδήποτε μεσολάβησει (Man-in-the-Middle) χρησιμοποιώντας sniffing εργαλεία (π.χ. Wireshark) μπορεί να διαβάσει αυτούσια passwords, cookies και δεδομένα.
* **HTTPS (Port 443):** Η ασφαλής (Secure) έκδοση. Το HTTP πακέτο εγκλείεται (encapsulated) μέσα στο πρωτόκολλο **TLS (Transport Layer Security)** (διάδοχος του παλιού SSL).

### Πώς λειτουργεί η κρυπτογράφηση TLS (με μια ματιά):
1. **Asymmetric Handshake:** Ο client συνδέεται στον server. Ο server στέλνει το **Ψηφιακό του Πιστοποιητικό (Digital Certificate)** το οποίο περιέχει το **Public Key** του (Δημόσιο Κλειδί).
2. **Verification:** Ο client επαληθεύει την εγκυρότητα του πιστοποιητικού μέσω ενός διεθνούς έμπιστου φορέα (Certificate Authority - CA).
3. **Symmetric Key Exchange:** Ο client δημιουργεί ένα τυχαίο κλειδί συνεδρίας (Session Key), το κρυπτογραφεί με το Public Key του server και του το στέλνει. Ο server είναι ο μόνος που μπορεί να το αποκρυπτογραφήσει χρησιμοποιώντας το κρυφό **Private Key** του.
4. **Bulk Encryption:** Από εδώ και πέρα, όλη η επικοινωνία κρυπτογραφείται με αυτό το κοινό Session Key (Συμμετρική κρυπτογράφηση - πολύ πιο γρήγορη).

## 🔀 8. Routing vs Switching & Domains

Η διακίνηση των δεδομένων βασίζεται σε δύο διαφορετικές λειτουργίες και επίπεδα του OSI.

### Switching (Layer 2)
* **Συσκευή:** Network Switch.
* **Λειτουργία:** Συνδέει συσκευές **εντός του ίδιου τοπικού δικτύου (LAN)**. Λειτουργεί με τις φυσικές διευθύνσεις **MAC Addresses**.
* **CAM Table (MAC Address Table):** Το switch διαβάζει το Source MAC κάθε εισερχόμενου frame, μαθαίνει σε ποια φυσική θύρα (Port) ανήκει και ενημερώνει τον πίνακα CAM. Όταν έρθει ένα πακέτο για εκείνη τη MAC, το προωθεί *αποκλειστικά* στη συγκεκριμένη θύρα (Point-to-Point).
* **Collision Domain:** Κάθε θύρα ενός Switch αποτελεί ένα απομονωμένο collision domain. Δεν υπάρχουν συγκρούσεις πακέτων (αντίθετα με τα παλιά Hubs).

### Routing (Layer 3)
* **Συσκευή:** Router.
* **Λειτουργία:** Συνδέει **διαφορετικά δίκτυα μεταξύ τους** (π.χ. το LAN της εταιρείας με το Internet). Λειτουργεί με λογικές διευθύνσεις **IP Addresses**.
* **Routing Table:** Ο router εξετάζει την IP προορισμού, συμβουλεύεται τον πίνακα δρομολόγησης και παίρνει την απόφαση για το ποιο είναι το επόμενο "άλμα" (Next Hop) που πρέπει να κάνει το πακέτο.
* **Broadcast Domain:** Οι routers **δεν επιτρέπουν τη διέλευση Broadcast μηνυμάτων**. Κάθε θύρα του router είναι ένα εντελώς ξεχωριστό Broadcast Domain.

## 🛡️ 9. VLANs & Trunking (Virtual LANs)

* **Ορισμός:** Τεχνολογία που επιτρέπει τον λογικό (λογισμικό) διαχωρισμό ενός φυσικού Switch σε πολλά "εικονικά" τοπικά δίκτυα (VLANs), απομονώνοντας πλήρως την κίνηση σαν να είχαμε διαφορετικά φυσικά switches.
* **Λειτουργία & Παράδειγμα:** Σε ένα Switch, οι θύρες 1-5 ρυθμίζονται στο VLAN 10 (Finance) και οι θύρες 6-10 στο VLAN 20 (HR). Ένα PC στο VLAN 10 δεν μπορεί να λάβει broadcast ή να επικοινωνήσει με PC στο VLAN 20, ακόμα κι αν είναι δίπλα-δίπλα στο ίδιο hardware.

### Τύποι Θυρών (Port Modes):
* **Access Port:** Μια θύρα που ανήκει σε **ένα και μοναδικό** VLAN. Χρησιμοποιείται για τη σύνδεση τελικών συσκευών (PCs, Printers, IP Phones).
* **Trunk Port:** Μια θύρα που επιτρέπει τη διέλευση κίνησης **όλων των VLANs ταυτόχρονα**. Χρησιμοποιείται για τη σύνδεση Switch-with-Switch ή Switch-with-Router.
* **IEEE 802.1Q (Dot1q):** Το standard πρωτόκολλο για Trunking. Προσθέτει ένα "Tag" (ετικέτα) 4-bytes μέσα στο Ethernet frame, το οποίο αναγράφει το VLAN ID, ώστε το απέναντι switch να ξέρει σε ποιο VLAN ανήκει το πακέτο.
* **Inter-VLAN Routing:** Επειδή τα VLANs είναι απομονωμένα στο Layer 2, για να επικοινωνήσουν μεταξύ τους πρέπει υποχρεωτικά να μεσολαβήσει μια συσκευή Layer 3. Αυτό επιτυγχάνεται είτε με έναν router (μέθοδος **Router-on-a-Stick** χρησιμοποιώντας sub-interfaces σε ένα trunk link) είτε με ένα **Layer 3 Switch** (χρησιμοποιώντας SVIs - Switch Virtual Interfaces).

## 📡 10. OSI Model (Το Θεωρητικό Θεμέλιο)

Το μοντέλο OSI (Open Systems Interconnection) είναι ένα θεωρητικό πλαίσιο αναφοράς 7 επιπέδων που τυποποιεί τις λειτουργίες των τηλεπικοινωνιών. Κάθε επίπεδο εκτελεί μια συγκεκριμένη εργασία και επικοινωνεί με το PDU (Protocol Data Unit) του αντίστοιχου επιπέδου στον παραλήπτη μέσω της διαδικασίας της **Ενθυλάκωσης (Encapsulation)**.

| Layer | Όνομα (Name) | PDU | Κύρια Λειτουργία | Παραδείγματα |
| :--- | :--- | :--- | :--- | :--- |
| **7** | **Application** | Data | Το σημείο εισόδου των εφαρμογών στο δίκτυο. Διασύνδεση χρήστη. | HTTP, HTTPS, DNS, FTP, SMTP, SSH |
| **6** | **Presentation**| Data | Μορφοποίηση, συμπίεση, κωδικοποίηση (ASCII/UTF) και κρυπτογράφηση. | SSL/TLS, JPEG, MP4, GIF |
| **5** | **Session** | Data | Έναρξη, διαχείριση, συγχρονισμός και τερματισμός των "συνεδριών" επικοινωνίας. | NetBIOS, RPC, SOCKS |
| **4** | **Transport** | Segment (TCP) / Datagram (UDP) | End-to-end μεταφορά, έλεγχος σφαλμάτων, ροής και διαχείριση θυρών (Ports). | TCP, UDP |
| **3** | **Network** | Packet | Λογική διευθυνσιοδότηση (IP) και εύρεση βέλτιστης διαδρομής (Routing). | IPv4, IPv6, ICMP, IPSec, Routers |
| **2** | **Data Link** | Frame | Φυσική διευθυνσιοδότηση (MAC addresses), έλεγχος σφαλμάτων μέσου, πρόσβαση στο media. | Ethernet (802.3), Wi-Fi (802.11), Switches |
| **1** | **Physical** | Bits | Φυσική μεταφορά των ωμών bits (ηλεκτρικό ρεύμα, φως, ραδιοκύματα). | Καλώδια UTP, Οπτικές Ίνες, Hubs, Connectors (RJ45) |

## 🌐 11. TCP/IP Model (Το Μοντέλο της Πράξης)

Το μοντέλο TCP/IP (ή DoD model) αναπτύχθηκε από τον στρατό των ΗΠΑ και είναι η πραγματική αρχιτεκτονική πάνω στην οποία βασίζεται το Internet. Είναι πιο απλό από το OSI και συμπυκνώνει τα επίπεδα σε 4 (ή 5 στην επικαιροποιημένη/μοντέρνα μορφή του).

| Modern TCP/IP Layer | Αντίστοιχα OSI Layers | Περιγραφή |
| :--- | :--- | :--- |
| **Application** | Layers 5, 6, 7 | Ενοποιεί τις υπηρεσίες εφαρμογής, την κωδικοποίηση και τον έλεγχο session. |
| **Transport** | Layer 4 | Host-to-host μεταφορά με flow control και ports (TCP/UDP). |
| **Internet** | Layer 3 | Διαχειρίζεται τη συσκευασία, διευθυνσιοδότηση και δρομολόγηση των πακέτων. |
| **Network Access** | Layers 1, 2 | Ορίζει τα φυσικά hardware χαρακτηριστικά, τις MAC διευθύνσεις και τα καλώδια. |

## 📮 12. Ports & Well-Known Services

Οι IPs βρίσκουν τη συσκευή στο δίκτυο, αλλά οι **Θύρες (Ports)** βρίσκουν την *конкretή εφαρμογή ή υπηρεσία* που τρέχει μέσα στη συσκευή. Οι θύρες παίρνουν τιμές από **0 έως 65535** και χωρίζονται σε 3 κατηγορίες:
* **Well-Known Ports (0 - 1023):** Δεσμευμένα για βασικά πρωτόκολλα συστήματος.
* **Registered Ports (1024 - 49151):** Για εφαρμογές τρίτων εταιρειών (π.χ. Βάσεις δεδομένων).
* **Dynamic / Ephemeral Ports (49152 - 65535):** Προσωρινές θύρες που ανοίγει αυτόματα ο Client για τη λήψη των απαντήσεων.

| Υπηρεσία (Service) | Θύρα (Port) | Πρωτόκολλο | Περιγραφή |
| :--- | :--- | :--- | :--- |
| **FTP** | 20 (Data), 21 (Control) | TCP | File Transfer Protocol (Μεταφορά αρχείων). |
| **SSH** | 22 | TCP | Secure Shell (Ασφαλής απομακρυσμένη διαχείριση CLI). |
| **Telnet** | 23 | TCP | Μη ασφαλής διαχείριση (Plain text - απαρχαιωμένο). |
| **SMTP** | 25 | TCP | Simple Mail Transfer Protocol (Αποστολή Email). |
| **DNS** | 53 | UDP / TCP | Domain Name System (Ανάλυση ονομάτων σε IPs). |
| **DHCP** | 67 (Server), 68 (Client) | UDP | Αυτόματη απόδοση ρυθμίσεων δικτύου. |
| **TFTP** | 69 | UDP | Trivial FTP (Πολύ απλή μεταφορά αρχείων χωρίς authentication). |
| **HTTP** | 80 | TCP | Hypertext Transfer Protocol (Μη κρυπτογραφημένο web). |
| **POP3** | 110 | TCP | Post Office Protocol v3 (Λήψη email - τα σβήνει από τον server). |

| **IMAP** | 143 | TCP | Internet Message Access Protocol (Λήψη email με συγχρονισμό). |

## 🔐 13. VPN (Virtual Private Network)

Το VPN δημιουργεί ένα **κρυπτογραφημένο εικονικό "τούνελ"** πάνω από το δημόσιο Internet, διασφαλίζοντας την Εμπιστευτικότητα (Confidentiality) και την Ακεραιότητα (Integrity) των δεδομένων.

### Κύριες Αρχιτεκτονικές:
* **Remote Access VPN (Client-to-Site):** Χρησιμοποιείται από απομακρυσμένους εργαζόμενους. Ο χρήστης τρέχει ένα λογισμικό (VPN Client), περνάει από authentication στο εταιρικό Firewall και αποκτά πρόσβαση στους εσωτερικούς πόρους της εταιρείας σαν να καθόταν στο γραφείο του.
* **Site-to-Site VPN:** Μόνιμη, σταθερή σύνδεση δύο ολόκληρων απομακρυσμένων δικτύων μέσω Internet. Υλοποιείται απευθείας μεταξύ των Routers/Firewalls των δύο κτιρίων (π.χ. Κεντρικά Αθήνας με Υποκατάστημα Λονδίνου).

### Κύρια Πρωτόκολλα Υλοποίησης:
* **IPsec (Internet Protocol Security):** Σουίτα πρωτοκόλλων στο Layer 3. Πολύ ισχυρή ασφάλεια. Αποτελείται από το **AH** (Authentication Header - για ακεραιότητα) και το **ESP** (Encapsulating Security Payload - για κρυπτογράφηση). Χρησιμοποιεί το **IKE** (v1/v2) για την ανταλλαγή κλειδιών.
* **OpenVPN:** Πρωτόκολλο ανοιχτού κώδικα που βασίζεται στο OpenSSL. Πολύ παραμετροποιήσιμο, μπορεί να τρέξει σε οποιοδήποτε port (παρακάμπτοντας Firewalls).
* **WireGuard:** Το νεότερο και πιο σύγχρονο πρωτόκολλο. Διαθέτει πολύ λιγότερες γραμμές κώδικα, είναι εξαιρετικά ελαφρύ, προσφέρει κορυφαία ασφάλεια και πολύ μεγαλύτερες ταχύτητες από τα IPsec/OpenVPN.

## 🏢 14. Network Devices (Ανάλυση Υλικού)

* **Hub (Layer 1):** Ένας απλός επαναλήπτης σήματος (Multiport Repeater). Ό,τι μπαίνει σε μια θύρα, αντιγράφεται και στέλνεται τυφλά σε όλες τις άλλες θύρες. Λειτουργεί σε κατάσταση **Half-Duplex** (μια συσκευή μιλάει τη φορά) και προκαλεί συνεχώς collisions.
* **Switch (Layer 2):** Έξυπνη συσκευή που βασίζεται σε Application-Specific Integrated Circuits (ASICs). Διαβάζει MAC addresses, απομονώνει τα collision domains και επιτρέπει **Full-Duplex** επικοινωνία (ταυτόχρονη αποστολή και λήψη).
* **Layer 3 Switch (Multilayer Switch):** Διαθέτει το hardware ενός switch αλλά περιλαμβάνει ASIC chips που μπορούν να διαβάσουν IPs και να κάνουν routing σε επίπεδο hardware με τεράστιες ταχύτητες (Wirespeed routing), χωρίς να επιβαρύνουν έναν κεντρικό router.
* **Router (Layer 3):** Συνδέει διαφορετικά δίκτυα (LAN-to-WAN). Παίρνει αποφάσεις βάσει IP, διαχειρίζεται το NAT, το QoS (Quality of Service) και τρέχει τα dynamic routing protocols.
* **Access Point (AP - Layer 1/2):** Μετατρέπει το ενσύρματο δίκτυο (Ethernet) σε ασύρματο (Wi-Fi 802.11) επιτρέποντας στις ασύρματες συσκευές να συνδεθούν στο LAN.
* **Firewall (Layers 3 - 7):** Η συσκευή θωράκισης του δικτύου.
  * *Stateful Inspection Firewalls:* Ελέγχουν τα πακέτα βάσει IP, Port και της κατάστασης της σύνδεσης (αν ανήκει σε ήδη εγκριμένο session).
  * *Next-Generation Firewalls (NGFW):* Σύγχρονα firewalls που κάνουν **Deep Packet Inspection (DPI)**. Μπορούν να ελέγξουν το περιεχόμενο στο Layer 7, να αναγνωρίσουν ποια ακριβώς εφαρμογή τρέχει (π.χ. ξεχωρίζουν το Facebook chat από ένα Facebook video) και διαθέτουν ενσωματωμένα συστήματα **IPS (Intrusion Prevention Systems)** και Antimalware.

## 🏗️ 15. Network Security Basics

### Το Μοντέλο AAA (Framework Ασφάλειας)
Αποτελεί το θεμέλιο της διαχείρισης πρόσβασης και ταυτότητας (Identity & Access Management) σε enterprise δίκτυα, και υλοποιείται μέσω πρωτοκόλλων όπως το **RADIUS** ή το **TACACS+**:
1. **Authentication (Πιστοποίηση):** *Ποιος είσαι;* Η διαδικασία επαλήθευσης της ταυτότητας (π.χ. εισαγωγή username/password, έλεγχος ψηφιακού πιστοποιητικού ή βιομετρικών δεδομένων).
2. **Authorization (Εξουσιοδότηση):** *Τι σου επιτρέπεται να κάνεις;* Αφού συνδεθείς, το σύστημα σου δίνει συγκεκριμένα δικαιώματα (π.χ. ένας Junior Engineer μπορεί να βλέπει το configuration - read only - αλλά δεν έχει δικαίωμα να κάνει αλλαγές).
3. **Accounting (Καταγραφή/Λογοδοσία):** *Τι έκανες και πότε;* Καταγράφει σε log αρχεία κάθε ενέργεια (π.χ. "Ο χρήστης X έκλεισε το Port 5 του Switch-A στις 14:00"). Απαραίτητο για troubleshooting και security auditing.

### Multi-Factor Authentication (MFA)
Η ασφάλεια βασίζεται σε 3 κύριους παράγοντες:
* Κάτι που *ξέρεις* (Password, PIN).
* Κάτι που *έχεις* (Κινητό τηλέφωνο, Hardware token, Smart Card).
* Κάτι που *είσαι* (Δακτυλικό αποτύπωμα, Face ID).
Το MFA απαιτεί τον συνδυασμό τουλάχιστον **δύο διαφορετικών παραγόντων** για να επιτρέψει την είσοδο.

### Αρχιτεκτονική Zero Trust
Η παραδοσιακή ασφάλεια βασιζόταν στο μοντέλο "Κάστρου" (εμπιστευόμαστε τυφλά όποιον βρίσκεται μέσα στο LAN). Το Zero Trust καταργεί αυτή τη φιλοσοφία με το αξίωμα: **"Never trust, always verify"**.
* Κάθε συσκευή και χρήστης θεωρείται απειλή, ακόμα κι αν είναι συνδεδεμένος με καλώδιο μέσα στο κτίριο της εταιρείας.
* Απαιτείται συνεχές re-authentication, μικρο-διαχωρισμός του δικτύου (Micro-segmentation) και εφαρμογή της αρχής των ελάχιστων προνομίων (Principle of Least Privilege).

## 🎯 16. Routing Protocols (Πρωτόκολλα Δρομολόγησης)

Όταν ένας router λαμβάνει ένα πακέτο, κοιτάει τον πίνακα δρομολόγησης (**Routing Table**). Οι διαδρομές καταχωρούνται εκεί με βάση την εξής ιεραρχία αξιοπιστίας, η οποία ορίζεται από το **Administrative Distance (AD)** (μικρότερο AD = πιο έμπιστη πηγή):
* **Directly Connected Networks:** Δίκτυα καρφωμένα πάνω στις θύρες του router ($AD = 0$).
* **Static Routes:** Χειροκίνητες διαδρομές γραμμένες από τον Admin ($AD = 1$).
* **Dynamic Routing Protocols:** Διαδρομές που μαθαίνονται αυτόματα από άλλους routers.

### Κατηγορίες Δυναμικών Πρωτοκόλλων:

#### 1. Distance Vector Protocols (Πρωτόκολλα Διανύσματος Απόστασης)
Οι routers δεν έχουν πλήρη εικόνα του δικτύου. Ξέρουν μόνο την απόσταση (metric) και την κατεύθυνση (Vector) προς την οποία πρέπει να στείλουν το πακέτο ("routing by rumor").
* **RIP (Routing Information Protocol):**
  * **Metric:** Hop Count (πόσους routers θα περάσει το πακέτο).
  * **Περιορισμός:** Μέγιστο όριο τα 15 hops. Στα 16 το δίκτυο θεωρείται unreachable. Είναι πολύ αργό στο convergence (χρόνος που χρειάζεται για να ενημερωθεί το δίκτυο αν πέσει μια γραμμή) και δεν υπολογίζει την ταχύτητα του καλωδίου.

#### 2. Link-State Protocols (Πρωτόκολλα Κατάστασης Συνδέσμου)
Κάθε router διαθέτει έναν πλήρη, πανομοιότυπο χάρτη ολόκληρης της τοπολογίας του δικτύου (Link-State Database).
* **OSPF (Open Shortest Path First):**
  * **Metric:** Cost (αντιστρόφως ανάλογο του Bandwidth των γραμμών. Ταχύτερη γραμμή = μικρότερο Cost).
  * **Αλγόριθμος:** Χρησιμοποιεί τον μαθηματικό αλγόριθμο **Dijkstra (Shortest Path First)**.
  * **Κλιμάκωση:** Χωρίζει το δίκτυο σε **Areas** για μείωση της επεξεργαστικής ισχύος. Το Area 0 ονομάζεται Backbone Area και όλα τα άλλα areas πρέπει να συνδέονται υποχρεωτικά πάνω του.

#### 3. Advanced Distance Vector / Hybrid Protocols
* **EIGRP (Enhanced Interior Gateway Routing Protocol):**
  * Πρωτόκολλο που αναπτύχθηκε από τη Cisco. Συνδυάζει την ταχύτητα των Link-State με την ευκολία των Distance Vector.
  * **Αλγόριθμος:** Χρησιμοποιεί τον αλγόριθμο **DUAL** για ακαριαίο convergence (κρατάει έτοιμη μια εναλλακτική διαδρομή backup, τη λεγόμενη Feasible Successor).
  * **Metric:** Σύνθετο (Composite metric) βασισμένο κυρίως στο Bandwidth και το Delay της γραμμής.

#### 4. Path-Vector Protocols (Πρωτόκολλα Εξωτερικής Δρομολόγησης)
* **BGP (Border Gateway Protocol):**
  * **Το Πρωτόκολλο του Internet.** Ενώ τα RIP, OSPF, EIGRP είναι IGPs (Interior Gateway Protocols) και τρέχουν *μέσα* σε μια εταιρεία, το BGP είναι EGP (Exterior Gateway Protocol).
  * Χρησιμοποιείται για να συνδέει διαφορετικά **Αυτόνομα Συστήματα (Autonomous Systems - AS)**, όπως μεγάλους τηλεπικοινωνιακούς παρόχους (ISPs), τη Google, τη Microsoft κλπ.
  * Δεν βασίζεται στην ταχύτητα, αλλά σε πολύπλοκα attributes και πολιτικές (Policies) που ορίζουν πώς θα ανταλλάσσεται η παγκόσμια κίνηση δεδομένων. Χωρίς το BGP, το Internet δεν θα μπορούσε να λειτουργήσει.
