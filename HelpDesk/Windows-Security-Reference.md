Δεν χρειάζεται προηγούμενη εμπειρία. Για κάθε εντολή θα βρεις:

- **Τι κάνει** και **πώς την τρέχεις**

> ⚠️ **Νομική & ηθική σημείωση:** Εκτέλεσε αυτές τις εντολές **μόνο σε συστήματα που σου ανήκουν ή για τα οποία έχεις ρητή γραπτή εξουσιοδότηση**. Η μη εξουσιοδοτημένη πρόσβαση ή ο έλεγχος ξένων συστημάτων είναι παράνομη. Για εξάσκηση χρησιμοποίησε **εικονική μηχανή (VM)** που δεν περιέχει πραγματικά δεδομένα.

## 0. Πριν ξεκινήσεις

### 0.1 Πώς ανοίγω τερματικό με δικαιώματα Διαχειριστή

Οι περισσότερες εντολές αυτού του οδηγού απαιτούν **αυξημένα δικαιώματα** (elevated). Χωρίς αυτά θα δεις μήνυμα όπως `Access is denied` ή κενά αποτελέσματα.

1. Πάτα το πλήκτρο **Windows** και πληκτρολόγησε `powershell` (ή `cmd`).
2. Κάνε **δεξί κλικ** στο αποτέλεσμα και επίλεξε **Εκτέλεση ως διαχειριστής** (Run as administrator).
3. Στο παράθυρο **Έλεγχος λογαριασμού χρήστη** πάτα **Ναι**.

Θα καταλάβεις ότι έχεις δικαιώματα διαχειριστή από τον τίτλο του παραθύρου, που ξεκινά με `Administrator:`.

### 0.2 Πώς αποθηκεύω το αποτέλεσμα μιας εντολής σε αρχείο

Στο Help Desk και στο Incident Response **τεκμηριώνεις τα πάντα**. Πρόσθεσε `>` και ένα όνομα αρχείου στο τέλος κάθε εντολής:

```cmd
schtasks /query /fo LIST /v > C:\Temp\tasks.txt
```

Το `>` δημιουργεί (ή αντικαθιστά) το αρχείο. Το `>>` προσθέτει στο τέλος ενός υπάρχοντος αρχείου.

### 0.3 CMD ή PowerShell;

| | CMD (Command Prompt) | PowerShell |
|---|---|---|
| Ηλικία | Παλιό, πολύ διαδεδομένο | Σύγχρονο, πιο ισχυρό |
| Έξοδος | Απλό κείμενο | Αντικείμενα (μπορείς να φιλτράρεις και να ταξινομήσεις) |
| Σε αυτόν τον οδηγό | Οι κλασικές εντολές | Οι σύγχρονες εναλλακτικές |

Οι περισσότερες κλασικές εντολές (`ipconfig`, `netsh`, `schtasks`) δουλεύουν και στα δύο.

### 0.4 Γλωσσάρι βασικών όρων

| Όρος | Απλή εξήγηση |
|------|--------------|
| **Malware** | Κακόβουλο λογισμικό (ιοί, trojans, ransomware κ.ά.) |
| **Persistence** | Τεχνικές με τις οποίες το malware «επιβιώνει» μετά από επανεκκίνηση, π.χ. μέσω Scheduled Task |
| **IoC (Indicator of Compromise)** | Ένδειξη ότι το σύστημα έχει παραβιαστεί (ύποπτο αρχείο, IP, διαγραμμένο log) |
| **Lateral Movement** | Η μετακίνηση ενός επιτιθέμενου από έναν υπολογιστή σε άλλους του ίδιου δικτύου |
| **ACL (Access Control List)** | Η λίστα που ορίζει ποιος έχει ποια δικαιώματα σε ένα αρχείο ή φάκελο |
| **Principle of Least Privilege** | Αρχή ελάχιστου δικαιώματος: κάθε χρήστης έχει μόνο όσα χρειάζεται |
| **EDR / Antivirus** | Λογισμικό που εντοπίζει και αντιδρά σε απειλές (π.χ. Microsoft Defender) |
| **SMB** | Πρωτόκολλο που χρησιμοποιούν τα Windows για κοινόχρηστους φακέλους και εκτυπωτές |
| **RDP** | Remote Desktop Protocol: απομακρυσμένη επιφάνεια εργασίας (θύρα TCP 3389) |
| **Brute-force** | Επίθεση με συνεχείς δοκιμές κωδικών μέχρι να βρεθεί ο σωστός |
| **Hash** | Μοναδικό «αποτύπωμα» ενός αρχείου. Αν αλλάξει έστω ένα byte, αλλάζει ολόκληρο το hash |
| **Rootkit** | Malware που κρύβεται βαθιά στο σύστημα και αποκρύπτει την παρουσία του |
| **Event ID** | Αριθμός που αναγνωρίζει τον τύπο ενός συμβάντος στα Event Logs |

## 1. Ανίχνευση Κακόβουλης Δραστηριότητας (Malware & Persistence Triage)

**Στόχος:** Όταν ένας υπολογιστής φαίνεται «περίεργος» (αργός, ανοίγει άγνωστα παράθυρα, ο ανεμιστήρας δουλεύει συνέχεια), εντοπίζουμε **ποιες διεργασίες τρέχουν**, **τι ξεκινά αυτόματα** και **αν το antivirus είναι ενεργό**.

### 1.1 Εντοπισμός ύποπτων διεργασιών

**Κλασική εντολή (CMD):**

```cmd
wmic process get name,executablepath,processid
```

**Σύγχρονη εναλλακτική (PowerShell), προτεινόμενη:**

```powershell
Get-CimInstance Win32_Process | Select-Object Name, ProcessId, ParentProcessId, ExecutablePath | Format-Table -AutoSize
```

> ℹ️ Το `wmic` είναι **απαρχαιωμένο (deprecated)**. Σε νεότερες εκδόσεις των Windows 11 μπορεί να μην είναι εγκατεστημένο. Η εντολή PowerShell πιο πάνω κάνει την ίδια δουλειά και προσθέτει το `ParentProcessId` (ποια διεργασία «γέννησε» την άλλη).

**Τι κάνει:** Εμφανίζει όλες τις τρέχουσες διεργασίες, το **όνομά** τους, το **PID** (αριθμός αναγνώρισης) και, το σημαντικότερο, την **ακριβή διαδρομή του `.exe`** στον δίσκο.

**Γιατί έχει σημασία:** Το όνομα ενός αρχείου μπορεί να παραποιηθεί εύκολα, η **τοποθεσία** του όμως προδίδει πολλά. Οι επιτιθέμενοι ονομάζουν συχνά το malware με όνομα νόμιμης διεργασίας (π.χ. `svchost.exe`) για να περάσει απαρατήρητο.

**Πώς διαβάζω το αποτέλεσμα:**

| Παρατήρηση | Φυσιολογικό ✅ | Ύποπτο 🚩 |
|------------|----------------|-----------|
| Τοποθεσία του `svchost.exe` | `C:\Windows\System32\svchost.exe` | `C:\Users\...\Downloads\`, `AppData`, `Temp`, `Public` |
| Γονική διεργασία (Parent) του `svchost.exe` | `services.exe` | Οποιαδήποτε άλλη, π.χ. `winword.exe` ή `cmd.exe` |
| Όνομα | `svchost.exe`, `lsass.exe` | Παραλλαγές με ορθογραφικές διαφορές: `svch0st.exe`, `scvhost.exe`, `1sass.exe` |
| `ExecutablePath` κενό | Για διεργασίες όπως `System` ή `Registry` είναι φυσιολογικό | Κενό σε ασυνήθιστη διεργασία μπορεί επίσης να σημαίνει ότι δεν έχεις αρκετά δικαιώματα |

**Επόμενο βήμα για ένα ύποπτο αρχείο:** Έλεγξε την ψηφιακή του υπογραφή:

```powershell
Get-AuthenticodeSignature "C:\Path\to\file.exe"
```

Το `Status` πρέπει να είναι `Valid` και ο εκδότης (Publisher) γνωστός, π.χ. Microsoft Corporation. Έπειτα υπολόγισε το hash του αρχείου (βλ. [ενότητα 5.2](#52-υπολογισμός-hash-αρχείου-sha256)).

> 🧠 **Σημαντικό:** Ένα εκτελέσιμο στον φάκελο Downloads είναι **πολύ ύποπτο**, αλλά δεν αποτελεί από μόνο του απόδειξη malware. Πολλά νόμιμα προγράμματα (portable apps) τρέχουν από εκεί. Συνδύασε πάντα πολλές ενδείξεις πριν καταλήξεις σε συμπέρασμα.
>
> ❌ **Μην τερματίζεις αμέσως** την ύποπτη διεργασία. Σημείωσε πρώτα PID, διαδρομή και hash και ακολούθησε το [Playbook της ενότητας 6](#6-μίνι-playbook-τι-κάνω-όταν-υποψιάζομαι-μόλυνση).

### 1.2 Έλεγχος Προγραμματισμένων Εργασιών (Scheduled Tasks)

```cmd
schtasks /query /fo TABLE /nh
```

**Ανάλυση παραμέτρων:**

| Παράμετρος | Σημασία |
|-----------|---------|
| `/query` | Εμφάνιση των εργασιών |
| `/fo TABLE` | Μορφή εξόδου: πίνακας (άλλες επιλογές: `LIST`, `CSV`) |
| `/nh` | *No Header*: χωρίς γραμμή επικεφαλίδων |

**Πιο αναλυτική εκδοχή**, που δείχνει *τι ακριβώς εκτελεί* κάθε εργασία:

```cmd
schtasks /query /fo LIST /v > C:\Temp\tasks.txt
```

**PowerShell εναλλακτική:**

```powershell
Get-ScheduledTask | Where-Object State -ne 'Disabled' | Select-Object TaskName, TaskPath, State
```

**Γιατί έχει σημασία:** Οι Scheduled Tasks είναι από τους πιο συνηθισμένους τρόπους **persistence**. Το malware δημιουργεί μια εργασία που το ξαναξεκινά σε κάθε εκκίνηση ή κάθε λίγα λεπτά.

**Τι ψάχνω στο αποτέλεσμα (κυρίως στο `/v`):**

- Πεδίο **`Task To Run`**: τι εκτελείται. Ύποπτα: διαδρομές σε `Temp`/`AppData`, εντολές `powershell -enc ...` (κωδικοποιημένο περιεχόμενο), `cmd /c` με μεγάλες περίεργες συμβολοσειρές.
- Πεδίο **`Run As User`**: αν τρέχει ως `SYSTEM` κάτι που δεν αναγνωρίζεις, χρειάζεται προσοχή.
- **Όνομα εργασίας**: τυχαίοι χαρακτήρες (π.χ. `a8Xk2Lq`) ή ονόματα που μιμούνται νόμιμα («GoogleUpdateTaskMachineCore» από λάθος φάκελο).
- **Τοποθεσία (TaskPath)**: οι εργασίες εκτός του `\Microsoft\Windows\` αξίζουν έναν πρόσθετο έλεγχο.

> ℹ️ Ένα κανονικό σύστημα Windows έχει **δεκάδες** εργασίες. Η ύπαρξη πολλών **δεν** είναι ένδειξη προβλήματος. Εστίασε σε όσες δεν αναγνωρίζεις και σε όσες τρέχουν αρχεία από ασυνήθιστους φακέλους.

### 1.3 Έλεγχος Οδηγών Φιλτραρίσματος Συστήματος Αρχείων

```cmd
fltmc filters
```

> 🔒 Απαιτεί δικαιώματα διαχειριστή.

**Τι κάνει:** Εμφανίζει τους **File System Filter Drivers**. Πρόκειται για οδηγούς που «κάθονται» ανάμεσα στο λειτουργικό και τον δίσκο και βλέπουν κάθε ανάγνωση/εγγραφή αρχείου. Τα antivirus και τα προγράμματα EDR χρησιμοποιούν αυτόν τον μηχανισμό για να σαρώνουν αρχεία σε πραγματικό χρόνο.

**Πώς διαβάζω το αποτέλεσμα:**

| Στήλη | Σημασία |
|-------|---------|
| `Filter Name` | Όνομα του οδηγού |
| `Num Instances` | Σε πόσους τόμους (volumes) είναι ενεργός |
| `Altitude` | Η «προτεραιότητα» του φίλτρου στη στοίβα |
| `Frame` | Εσωτερική πληροφορία του Filter Manager |

**Τι ψάχνω:**

- Το **`WdFilter`** είναι ο οδηγός του Microsoft Defender. Αν το βλέπεις, ο Defender λειτουργεί στο επίπεδο του συστήματος αρχείων.
- Αν χρησιμοποιείς άλλο antivirus/EDR, θα δεις τον δικό του οδηγό με διαφορετικό όνομα (ανάλογα με τον κατασκευαστή).
- Αν **δεν** βλέπεις κανέναν οδηγό προστασίας ενώ αναμένεις να υπάρχει, το προϊόν ασφαλείας μπορεί να είναι απενεργοποιημένο ή να έχει παραβιαστεί.
- **Άγνωστο φίλτρο** που δεν αντιστοιχεί σε γνωστό λογισμικό αξίζει ερευνάς. Δεν αποτελεί απόδειξη rootkit, αλλά είναι λόγος να ζητήσεις δεύτερη γνώμη ή να κάνεις escalate.

## 2. Έλεγχος Πρόσβασης & Δικαιωμάτων (Access Control & Privilege Audit)

**Στόχος:** Εφαρμογή της **αρχής του ελάχιστου δικαιώματος**: κάθε χρήστης και κάθε πρόγραμμα έχει πρόσβαση μόνο σε ό,τι χρειάζεται για τη δουλειά του και τίποτα παραπάνω.

### 2.1 Διαχείριση δικαιωμάτων φακέλων με `icacls`

**Προβολή των τρεχόντων δικαιωμάτων ενός φακέλου (ασφαλές):**

```cmd
icacls "C:\Data\Confidential"
```

**Πώς διαβάζω το αποτέλεσμα:**

```text
C:\Data\Confidential BUILTIN\Administrators:(I)(OI)(CI)(F)
                     NT AUTHORITY\SYSTEM:(I)(OI)(CI)(F)
                     BUILTIN\Users:(I)(OI)(CI)(RX)
```

| Σύμβολο | Σημασία |
|---------|---------|
| `F` | Full control (πλήρης έλεγχος) |
| `M` | Modify (τροποποίηση) |
| `RX` | Read & Execute (ανάγνωση και εκτέλεση) |
| `R` | Read (μόνο ανάγνωση) |
| `(I)` | Inherited: κληρονομείται από τον γονικό φάκελο |
| `(OI)` / `(CI)` | Ισχύει για αρχεία (Object Inherit) / υποφακέλους (Container Inherit) |

**Η εντολή του οδηγού (προσοχή!):**

```cmd
icacls "C:\Data\Confidential" /inheritance:r
```

Η παράμετρος `/inheritance:r` **αφαιρεί όλα τα κληρονομούμενα δικαιώματα** από τον φάκελο.

> 🚨 **ΠΡΟΕΙΔΟΠΟΙΗΣΗ:** Αν ο φάκελος δεν έχει ήδη *ρητά* (explicit) δικαιώματα, η εντολή τον αφήνει **χωρίς κανένα δικαίωμα για κανέναν**, ακόμη και για διαχειριστές. Μπορεί να κλειδωθεί εντελώς η πρόσβαση. **Μην την τρέξεις ποτέ ως έχει σε παραγωγικό φάκελο.**

**Ασφαλής διαδικασία, βήμα προς βήμα:**

**Βήμα 1: Αντίγραφο ασφαλείας των τρεχόντων δικαιωμάτων**

```cmd
icacls "C:\Data\Confidential" /save "C:\Backup\Confidential-ACL.txt" /t
```

**Βήμα 2: Αφαίρεση κληρονομιάς και *ταυτόχρονη* χορήγηση των απαραίτητων δικαιωμάτων**

```cmd
icacls "C:\Data\Confidential" /inheritance:r /grant:r "BUILTIN\Administrators:(OI)(CI)F" "NT AUTHORITY\SYSTEM:(OI)(CI)F" "DOMAIN\HR-Team:(OI)(CI)M"
```

- `/grant:r`: αντικαθιστά (replace) τα δικαιώματα του συγκεκριμένου λογαριασμού.
- Άλλαξε το `DOMAIN\HR-Team` με την πραγματική ομάδα ή τον χρήστη. Σε υπολογιστή εκτός domain χρησιμοποίησε `ΟΝΟΜΑ_ΥΠΟΛΟΓΙΣΤΗ\Χρήστης`.
- Άφησε **πάντα** Administrators και SYSTEM, αλλιώς θα δυσκολευτούν οι εργασίες συντήρησης και τα αντίγραφα ασφαλείας.

**Βήμα 3: Επαλήθευση**

```cmd
icacls "C:\Data\Confidential"
```

**Αν κάτι πάει στραβά, επαναφορά** (η εντολή δίνεται στον *γονικό* φάκελο):

```cmd
icacls "C:\Data" /restore "C:\Backup\Confidential-ACL.txt"
```

> 🧪 Δοκίμασε πρώτα σε **δοκιμαστικό φάκελο** ή σε VM.

### 2.2 Ενεργές απομακρυσμένες συνδέσεις με `net session`

```cmd
net session
```

> 🔒 Απαιτεί δικαιώματα διαχειριστή.

**Τι κάνει:** Εμφανίζει ποιοι **άλλοι υπολογιστές είναι συνδεδεμένοι αυτή τη στιγμή σε αυτό το μηχάνημα** μέσω SMB (κοινόχρηστοι φάκελοι, admin shares όπως το `C$`).

**Παράδειγμα εξόδου:**

```text
Computer               User name            Client Type       Opens Idle time
-------------------------------------------------------------------------------
\\192.168.1.45         Administrator                              1 00:00:12
```

**Τι ψάχνω:**

- **Σε σταθμό εργασίας (workstation):** Η φυσιολογική απάντηση είναι συνήθως `There are no entries in the list`. Αν άλλος υπολογιστής είναι συνδεδεμένος, ρώτα ποιος και γιατί.
- **Λογαριασμός με δικαιώματα διαχειριστή** από άγνωστη IP ή εκτός ωραρίου είναι ισχυρή ένδειξη **lateral movement**.
- **Σε file server** είναι φυσιολογικό να υπάρχουν πολλές συνεδρίες. Εστίασε σε ασυνήθιστα πρότυπα, όπως άγνωστες IP ή λογαριασμούς που δεν θα έπρεπε να χρησιμοποιούν τον server.

**Συμπληρωματικές εντολές:**

```cmd
net share
```

Εμφανίζει τους φακέλους που **μοιράζεται** το μηχάνημα. Έλεγξε ότι δεν υπάρχουν κοινόχρηστοι φάκελοι που δεν γνωρίζεις.

### 2.3 Αποθηκευμένα διαπιστευτήρια με `cmdkey`

```cmd
cmdkey /list
```

**Τι κάνει:** Εμφανίζει τα **διαπιστευτήρια που είναι αποθηκευμένα στον Credential Manager των Windows** για τον τρέχοντα χρήστη, π.χ. για δικτυακούς δίσκους ή απομακρυσμένους υπολογιστές.

> ℹ️ **Σημαντική διευκρίνιση:** Η εντολή εμφανίζει το **όνομα-στόχο (Target)** και το **όνομα χρήστη**, **όχι** τους ίδιους τους κωδικούς. Η ύπαρξη αποθηκευμένων διαπιστευτηρίων παραμένει ρίσκο, επειδή ένας επιτιθέμενος που ελέγχει τη συνεδρία του χρήστη μπορεί να τα χρησιμοποιήσει ή να επιχειρήσει να τα εξαγάγει με άλλα εργαλεία (Credential Harvesting).

**Παράδειγμα εξόδου:**

```text
Target: Domain:target=SERVER01
Type: Domain Password
User: CORP\admin.user
```

**Τι ψάχνω:**

- **Διαπιστευτήρια διαχειριστή** (`admin`, `Administrator`, `svc_...`) αποθηκευμένα σε κοινόχρηστο ή μη ασφαλή υπολογιστή.
- Στόχους που δεν αναγνωρίζεις ή δεν θα έπρεπε να χρησιμοποιεί ο συγκεκριμένος χρήστης.

**Αφαίρεση ενός αποθηκευμένου διαπιστευτηρίου:**

```cmd
cmdkey /delete:SERVER01
```

> ⚠️ Πριν διαγράψεις, ενημέρωσε τον χρήστη: μπορεί να χάσει αυτόματη πρόσβαση σε δικτυακούς δίσκους.

## 3. Θωράκιση Δικτύου (Host-Based Firewall Hardening)

**Στόχος:** Μείωση της **επιφάνειας επίθεσης (Attack Surface Reduction)**: όσο λιγότερες «πόρτες» είναι ανοιχτές προς το δίκτυο, τόσο λιγότερες ευκαιρίες έχει ο επιτιθέμενος.

### 3.1 Έλεγχος κατάστασης του Windows Defender Firewall

```cmd
netsh advfirewall show allprofiles
```

**PowerShell εναλλακτική:**

```powershell
Get-NetFirewallProfile | Select-Object Name, Enabled
```

**Τι κάνει:** Δείχνει την κατάσταση του τείχους προστασίας για τα **τρία προφίλ**:

| Προφίλ | Πότε ισχύει |
|--------|-------------|
| **Domain** | Ο υπολογιστής είναι συνδεδεμένος στο εταιρικό domain |
| **Private** | Οικιακό ή έμπιστο δίκτυο |
| **Public** | Δημόσιο δίκτυο (καφετέρια, αεροδρόμιο) |

**Τι ψάχνω:** Για **κάθε** προφίλ η γραμμή `State` πρέπει να δείχνει **`ON`**.

**Αν βρεις `OFF`:** Ρώτησε πρώτα αν υπάρχει εγκεκριμένος λόγος (π.χ. άλλο firewall τρίτου). Αν όχι, ενεργοποίησέ το:

```cmd
netsh advfirewall set allprofiles state on
```

> 🚩 Ένα απενεργοποιημένο firewall χωρίς εξήγηση μπορεί να είναι ένδειξη ότι το σύστημα έχει παραβιαστεί ή ότι ο χρήστης έχει αλλάξει ρυθμίσεις.

---

### 3.2 Αποκλεισμός εισερχόμενων συνδέσεων RDP

```cmd
netsh advfirewall firewall add rule name="Block inbound RDP" dir=in action=block protocol=TCP localport=3389
```

**Ανάλυση παραμέτρων:**

| Παράμετρος | Σημασία |
|-----------|---------|
| `add rule` | Δημιουργία νέου κανόνα |
| `name="..."` | Όνομα του κανόνα (επέλεξε κάτι κατανοητό) |
| `dir=in` | Κατεύθυνση: **εισερχόμενη** κίνηση |
| `action=block` | Ενέργεια: **αποκλεισμός** |
| `protocol=TCP` | Πρωτόκολλο TCP |
| `localport=3389` | Η θύρα του Remote Desktop |

**Τι κάνει:** Μπλοκάρει κάθε εισερχόμενη σύνδεση Remote Desktop προς αυτό το μηχάνημα. Χρησιμοποιείται για άμεση προστασία από **brute-force επιθέσεις** RDP.

> 🚨 **Προσοχή, μπορεί να κόψεις τον εαυτό σου έξω:**
> - Αν είσαι συνδεδεμένος στο μηχάνημα **μέσω RDP**, ο κανόνας μπορεί να διακόψει τη σύνδεσή σου και να μην μπορείς να τον αναιρέσεις εξ αποστάσεως.
> - Οι κανόνες **block υπερισχύουν** των κανόνων allow.
> - Σε εταιρικό περιβάλλον, οι πολιτικές (GPO) μπορεί να αλλάξουν ή να αντικαταστήσουν τον κανόνα σου. Ενημέρωσε την ομάδα ασφάλειας ή δικτύων πριν κάνεις αλλαγές.

**Επαλήθευση ότι ο κανόνας υπάρχει:**

```cmd
netsh advfirewall firewall show rule name="Block inbound RDP"
```

**Έλεγχος αν το RDP «ακούει» στο μηχάνημα:**

```cmd
netstat -ano | findstr :3389
```

**Αναίρεση (διαγραφή του κανόνα):**

```cmd
netsh advfirewall firewall delete rule name="Block inbound RDP"
```

**Πιο ώριμες πρακτικές** (πέρα από τον πλήρη αποκλεισμό):

- Επέτρεψε το RDP **μόνο από συγκεκριμένες IP** με την παράμετρο `remoteip=`.
- Ενεργοποίησε το **Network Level Authentication (NLA)**.
- Πρόσβαση μέσω **VPN** και όχι απευθείας από το διαδίκτυο.
- **Πολυπαραγοντική ταυτοποίηση (MFA)** και ισχυροί κωδικοί.

## 4. Έλεγχος Αρχείων Καταγραφής (Security Event Log Auditing)

**Στόχος:** Τα Event Logs είναι το «μαύρο κουτί» του υπολογιστή. Καταγράφουν ποιος συνδέθηκε, πότε, και τι άλλαξε. Οι επιτιθέμενοι προσπαθούν συχνά να τα διαγράψουν για να σβήσουν τα ίχνη τους.

### 4.1 Ανάγνωση των πρόσφατων συμβάντων ασφαλείας

```cmd
wevtutil qe Security /f:text /c:5 /rd:true
```

> 🔒 Η ανάγνωση του Security log απαιτεί δικαιώματα διαχειριστή.

**Ανάλυση παραμέτρων:**

| Τμήμα | Σημασία |
|-------|---------|
| `qe` | *Query Events*: αναζήτηση συμβάντων |
| `Security` | Το όνομα του log |
| `/f:text` | Μορφή εξόδου: αναγνώσιμο κείμενο |
| `/c:5` | *Count*: μόνο 5 συμβάντα |
| `/rd:true` | *Reverse Direction*: πρώτα τα **πιο πρόσφατα** |

**Φιλτράρισμα ανά Event ID** (πολύ πιο χρήσιμο στην πράξη). Παράδειγμα, οι τελευταίες 10 αποτυχημένες συνδέσεις:

```cmd
wevtutil qe Security /q:"*[System[(EventID=4625)]]" /c:10 /rd:true /f:text
```

**PowerShell εναλλακτική:**

```powershell
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4625} -MaxEvents 10
```

**Βασικά Event IDs που πρέπει να γνωρίζεις:**

| Event ID | Σημασία | Τι μπορεί να υποδεικνύει |
|:--------:|---------|--------------------------|
| **4624** | Επιτυχής σύνδεση | Κανονική δραστηριότητα. Ύποπτη αν είναι εκτός ωραρίου ή από άγνωστη πηγή |
| **4625** | **Αποτυχημένη** σύνδεση | Πολλά σε σύντομο χρόνο: πιθανή brute-force επίθεση |
| **4672** | Ειδικά προνόμια σε νέα σύνδεση | Σύνδεση λογαριασμού με δικαιώματα διαχειριστή |
| **4720** | Δημιουργία νέου λογαριασμού χρήστη | Ανεπιθύμητη αν δεν την έκανε εξουσιοδοτημένο πρόσωπο |
| **4732** | Προσθήκη μέλους σε τοπική ομάδα ασφαλείας | Πιθανή κλιμάκωση δικαιωμάτων (π.χ. προσθήκη στους Administrators) |
| **4698** | Δημιουργία Scheduled Task | Πιθανό persistence |
| **1102** | **Το Security log διαγράφηκε** | 🚩 Ισχυρό IoC (βλ. 4.2) |

**Πώς διαβάζω ένα συμβάν 4625:**

- **Account Name**: ο λογαριασμός που δοκιμάστηκε.
- **Source Network Address**: από ποια IP ήρθε η προσπάθεια.
- **Logon Type**: `3` = μέσω δικτύου, `10` = Remote Desktop (RDP), `2` = τοπική σύνδεση.
- **Failure Reason / Status**: γιατί απέτυχε (λάθος κωδικός, ανύπαρκτος χρήστης κ.λπ.).

> 🚩 **Ένδειξη επίθεσης:** Δεκάδες ή εκατοντάδες `4625` από την **ίδια IP** μέσα σε λίγα λεπτά, ιδιαίτερα με `Logon Type 10`, δείχνουν brute-force προς RDP. Επόμενο βήμα: δες την [ενότητα 3.2](#32-αποκλεισμός-εισερχόμενων-συνδέσεων-rdp).

---

### 4.2 Διαγραφή του Security Log και πώς το εντοπίζεις

```cmd
wevtutil cl Security
```

**Τι κάνει:** `cl` = *Clear Log*. Διαγράφει **οριστικά** όλα τα συμβάντα του Security log.

> 🚫 **ΜΗΝ τρέξεις ποτέ αυτή την εντολή σε παραγωγικό ή ύποπτο σύστημα.** Η διαγραφή είναι **μη αναστρέψιμη** και καταστρέφει τεκμήρια. Την παρουσιάζουμε μόνο για να **αναγνωρίζεις** τι κάνουν οι επιτιθέμενοι.

**Πώς εντοπίζω ότι έγινε διαγραφή (IoC):**

Όταν διαγράφεται το Security log, τα Windows καταγράφουν αυτόματα ένα νέο συμβάν:

| Log | Event ID | Σημασία |
|-----|:--------:|---------|
| Security | **1102** | Το Security log καθαρίστηκε |
| System | **104** | Ένα log (π.χ. το System) καθαρίστηκε |

```cmd
wevtutil qe Security /q:"*[System[(EventID=1102)]]" /f:text /c:5 /rd:true
```

Αν υπάρχει συμβάν **1102** που δεν αναμένεις, αντιμετώπισέ το ως **σοβαρή ένδειξη παραβίασης** και κάνε άμεσα escalate.

> ℹ️ Ένα *εντελώς άδειο* log δεν είναι απαραίτητα ένδειξη διαγραφής. Μπορεί απλώς να μην έχει ενεργοποιηθεί ο έλεγχος (auditing) ή το log να έχει «γυρίσει» λόγω μεγέθους. Το συμβάν **1102** είναι η πιο αξιόπιστη απόδειξη.

**Καλή πρακτική: πάρε αντίγραφο των logs ως τεκμήριο:**

```cmd
wevtutil epl Security C:\Evidence\Security.evtx
```

Το `epl` (*Export Log*) αποθηκεύει το log σε αρχείο `.evtx` που μπορεί να αναλυθεί αργότερα ή να παραδοθεί στην ομάδα ασφάλειας.

## 5. Κρυπτογράφηση & Ακεραιότητα (Data Protection & Cryptography)

### 5.1 Έλεγχος κατάστασης BitLocker

```cmd
manage-bde -status
```

> 🔒 Απαιτεί δικαιώματα διαχειριστή. Το BitLocker δεν περιλαμβάνεται στην έκδοση Windows Home (η οποία έχει πιο περιορισμένη «Κρυπτογράφηση συσκευής»).

**Τι κάνει:** Δείχνει αν οι δίσκοι του υπολογιστή είναι κρυπτογραφημένοι με **BitLocker**. Αυτό λέγεται προστασία **Data-at-Rest** (δεδομένα «σε ηρεμία»). Αν ένα laptop κλαπεί, τα δεδομένα δεν μπορούν να διαβαστούν χωρίς το κλειδί.

**Πώς διαβάζω το αποτέλεσμα:**

| Πεδίο | Τι πρέπει να δω |
|-------|-----------------|
| **Conversion Status** | `Fully Encrypted` (πλήρως κρυπτογραφημένο) |
| **Percentage Encrypted** | `100%` |
| **Encryption Method** | π.χ. `XTS-AES 128` ή `XTS-AES 256` |
| **Protection Status** | **`Protection On`** |
| **Key Protectors** | π.χ. `TPM`, `Numerical Password` (κλειδί ανάκτησης) |

> ⚠️ **Προσοχή στη λεπτομέρεια:** Ο δίσκος μπορεί να δείχνει `Fully Encrypted` και ταυτόχρονα `Protection Off`. Αυτό σημαίνει ότι η προστασία έχει **ανασταλεί (suspended)** και το κλειδί είναι προσωρινά εκτεθειμένο. Άρα τα δεδομένα **δεν** είναι πραγματικά ασφαλή. Ο έλεγχος πρέπει να γίνεται και στα δύο πεδία.

**Επιπλέον καλές πρακτικές:**

- Φύλαξε το **κλειδί ανάκτησης (recovery key)** σε ασφαλές μέρος (π.χ. Active Directory ή λογαριασμός Microsoft). Χωρίς αυτό, ένα πρόβλημα στο hardware μπορεί να κλειδώσει οριστικά τα δεδομένα.
- Έλεγξε **όλους** τους δίσκους/τόμους, όχι μόνο το `C:`.

---

### 5.2 Υπολογισμός hash αρχείου (SHA256)

```cmd
certutil -hashfile "C:\Path\to\file.exe" SHA256
```

**PowerShell εναλλακτική:**

```powershell
Get-FileHash "C:\Path\to\file.exe" -Algorithm SHA256
```

**Τι κάνει:** Υπολογίζει το **κρυπτογραφικό αποτύπωμα (hash)** του αρχείου: μια μοναδική σειρά 64 χαρακτήρων (για SHA256). Αν αλλάξει έστω και ένα byte του αρχείου, το hash αλλάζει ολοκληρωτικά.

**Παράδειγμα εξόδου:**

```text
SHA256 hash of file.exe:
3a7bd3e2360a3d29eea436fcfb7e44c735d117c42d1c1835420b6b9942dd4f1b
CertUtil: -hashfile command completed successfully.
```

*(Το hash είναι ενδεικτικό.)*

**Δύο βασικές χρήσεις:**

1. **Έλεγχος ακεραιότητας:** Σύγκρινε το hash με αυτό που δημοσιεύει ο κατασκευαστής. Αν ταιριάζει, το αρχείο δεν έχει αλλοιωθεί κατά τη λήψη.
2. **Έλεγχος αν είναι γνωστό malware:** Αναζήτησε το hash στο [VirusTotal](https://www.virustotal.com) (πεδίο *Search*).

> 🔐 **Καλή πρακτική:** Αναζήτησε το **hash** και **μην ανεβάζεις** εμπιστευτικά ή εταιρικά αρχεία στο VirusTotal, γιατί οι αναρτήσεις γίνονται προσβάσιμες σε τρίτους.
>
> ℹ️ Αν το hash **δεν βρεθεί** στο VirusTotal, αυτό **δεν σημαίνει** ότι το αρχείο είναι ασφαλές. Μπορεί απλώς να μην έχει ξαναδεί ποτέ.

## 6. Μίνι Playbook: Τι κάνω όταν υποψιάζομαι μόλυνση

Οι εντολές είναι εργαλεία. Η **σωστή σειρά ενεργειών** είναι εξίσου σημαντική:

| Βήμα | Ενέργεια | Λεπτομέρειες |
|:----:|----------|--------------|
| **1** | **Μην πανικοβληθείς** | Μην κλείσεις, μην κάνεις format, μην διαγράψεις τίποτα. Η μνήμη και τα logs χάνονται με την επανεκκίνηση. |
| **2** | **Τεκμηρίωσε** | Σημείωσε ώρα, όνομα υπολογιστή, χρήστη, τι παρατήρησε ο χρήστης. Αποθήκευσε τα αποτελέσματα των εντολών σε αρχεία (`> file.txt`). |
| **3** | **Συλλογή ενδείξεων** | Διεργασίες (1.1), Scheduled Tasks (1.2), συνδέσεις (`netstat -ano`), logs (4.1). Εξαγωγή του log με `wevtutil epl`. |
| **4** | **Απομόνωση** | Αποσύνδεσε τον υπολογιστή από το δίκτυο (καλώδιο ή Wi-Fi). Μην τον σβήσεις, εκτός αν σου το ζητήσει η ομάδα ασφάλειας. |
| **5** | **Escalate** | Ενημέρωσε τον υπεύθυνο ασφάλειας ή τον επόπτη σου με όλα τα στοιχεία. **Η δουλειά του Help Desk είναι η έγκαιρη αναγνώριση και σωστή προώθηση**, όχι να «καθαρίσει» μόνος του ένα σοβαρό περιστατικό. |
| **6** | **Ανάκαμψη** | Μετά την έγκριση της ομάδας ασφάλειας: καθαρισμός/επανεγκατάσταση, αλλαγή κωδικών, έλεγχος άλλων συστημάτων. |

## 7. Συγκεντρωτικός Πίνακας

Το **MITRE ATT&CK** είναι παγκόσμια βάση γνώσης με τις τεχνικές των επιτιθέμενων. Ο πίνακας συνδέει κάθε εντολή με το τι ελέγχει.

| Εντολή | Τι ελέγχω | Admin; | Σχετική τεχνική MITRE ATT&CK |
|--------|-----------|:------:|-------------------------------|
| `Get-CimInstance Win32_Process` (ή `wmic process ...`) | Ύποπτες διεργασίες και διαδρομές | Προτείνεται | T1036.005: Masquerading (Match Legitimate Name or Location) |
| `schtasks /query /fo LIST /v` | Persistence μέσω εργασιών | Όχι | T1053.005: Scheduled Task |
| `fltmc filters` | Κατάσταση antivirus/EDR στο επίπεδο αρχείων | Ναι | T1562: Impair Defenses |
| `icacls` | Δικαιώματα φακέλων (ACLs) | Ναι (για αλλαγές) | Ελάχιστο δικαίωμα (hardening) |
| `net session` | Απομακρυσμένες συνδέσεις SMB | Ναι | T1021.002: SMB/Windows Admin Shares |
| `cmdkey /list` | Αποθηκευμένα διαπιστευτήρια | Όχι | T1555.004: Windows Credential Manager |
| `netsh advfirewall show allprofiles` | Ενεργό firewall | Ναι | T1562.004: Disable or Modify System Firewall |
| `netsh advfirewall ... block 3389` | Αποκλεισμός RDP | Ναι | T1021.001: Remote Desktop Protocol / T1110: Brute Force |
| `wevtutil qe Security ...` | Ανάλυση συμβάντων | Ναι | T1110: Brute Force (Event 4625) |
| `wevtutil cl Security` | Διαγραφή logs (**μη ασφαλής**) | Ναι | T1070.001: Clear Windows Event Logs |
| `manage-bde -status` | Κρυπτογράφηση δίσκου | Ναι | Data-at-Rest protection |
| `certutil -hashfile` | Ακεραιότητα και ταυτοποίηση αρχείου | Όχι | Threat intelligence / file reputation |

## 8. Συχνά Λάθη Αρχαρίων

1. **Τρέχουν εντολές χωρίς δικαιώματα διαχειριστή** και ερμηνεύουν το κενό αποτέλεσμα ως «όλα καλά».
2. **Τερματίζουν αμέσως ύποπτες διεργασίες** και χάνουν πολύτιμα στοιχεία. Πρώτα τεκμηρίωση.
3. **Εφαρμόζουν `icacls /inheritance:r` χωρίς backup** και κλειδώνουν φακέλους.
4. **Μπλοκάρουν το RDP ενώ είναι συνδεδεμένοι με RDP.**
5. **Υποθέτουν ότι ένα άγνωστο πρόγραμμα είναι malware** (ή ότι ένα γνωστό όνομα είναι πάντα ασφαλές). Οι ενδείξεις πρέπει να συνδυάζονται.
6. **Ανεβάζουν εμπιστευτικά αρχεία σε δημόσιες υπηρεσίες σάρωσης.**
7. **Προσπαθούν να λύσουν μόνοι σοβαρό περιστατικό** αντί να κάνουν escalate.
8. **Δοκιμάζουν επικίνδυνες εντολές σε παραγωγικά συστήματα** αντί για VM.
