# Troubleshooting Runbooks

Step-by-step οδηγίες (runbooks) για τα πιο συνηθισμένα προβλήματα που αντιμετωπίζει η ομάδα IT. Στόχος είναι η γρήγορη, συνεπής και τεκμηριωμένη επίλυση, ανεξάρτητα από το ποιος τεχνικός αναλαμβάνει το ticket.

## Πώς να χρησιμοποιήσετε αυτό το έγγραφο

1. Εντοπίστε το πρόβλημα στον πίνακα περιεχομένων.
2. Ακολουθήστε τα βήματα με τη σειρά — μην τα παραλείπετε, ακόμα κι αν φαίνονται προφανή.
3. Καταγράψτε στο ticket ποιο βήμα έλυσε το πρόβλημα (βοηθά στη βελτίωση του runbook).
4. Αν κανένα βήμα δεν δουλέψει, ακολουθήστε τη διαδικασία **Escalation** στο τέλος κάθε runbook.

## 1. Χρήστης δεν μπορεί να συνδεθεί (Login issues)

**Συμπτώματα:** Ο χρήστης αναφέρει "λάθος κωδικός" ή "ο λογαριασμός είναι κλειδωμένος" παρόλο που εισάγει σωστά τα στοιχεία του.

### Βήματα

1. Επιβεβαιώστε το username του χρήστη (π.χ. `gpapadopoulos`, όχι το email).

2. Ελέγξτε στο Active Directory αν ο λογαριασμός είναι κλειδωμένος:

```powershell
Get-ADUser -Identity <username> -Properties LockedOut, PasswordExpired, Enabled
```

3. Αν είναι κλειδωμένος, ξεκλειδώστε:

```powershell
Unlock-ADAccount -Identity <username>
```

4. Αν ο κωδικός έχει λήξει, κάντε reset και ενημερώστε τον χρήστη να τον αλλάξει στην επόμενη σύνδεση:

```powershell
Set-ADAccountPassword -Identity <username> -Reset -NewPassword (ConvertTo-SecureString "TempPass123!" -AsPlainText -Force)
Set-ADUser -Identity <username> -ChangePasswordAtLogon $true
```

5. Ελέγξτε αν ο λογαριασμός είναι ενεργός (`Enabled = True`). Αν όχι, ενεργοποιήστε τον μόνο μετά από επιβεβαίωση ότι είναι εξουσιοδοτημένο.

6. Ζητήστε από τον χρήστη να δοκιμάσει ξανά. Αν αποτύχει σε shared PC, ελέγξτε για cached credentials (`Credential Manager` στα Windows).

### Escalation

Αν το πρόβλημα επιμένει μετά τα παραπάνω, ελέγξτε συγχρονισμό ρολογιού (Kerberos time skew) ή replication issues μεταξύ Domain Controllers, και προωθήστε στο Tier 2 / AD administrator.

## 2. Αργή σύνδεση δικτύου / VPN

**Συμπτώματα:** Αργή περιήγηση, timeouts, VPN αποσυνδέεται συχνά.

### Βήματα

1. Ζητήστε από τον χρήστη να τρέξει speed test (π.χ. speedtest.net) και καταγράψτε τα αποτελέσματα.
2. Ελέγξτε αν το πρόβλημα υπάρχει και σε ενσύρματη σύνδεση (εξαιρεί Wi-Fi ζητήματα).
3. Επιβεβαιώστε ότι δεν τρέχει bandwidth-heavy εφαρμογή στο background (backups, updates, cloud sync).
4. Restart του router/access point αν είναι τοπικός εξοπλισμός υπό τον έλεγχό σας.
5. Για VPN: ελέγξτε τα logs του VPN client για σφάλματα (auth failures, timeout).
6. Δοκιμάστε εναλλακτικό VPN protocol αν είναι διαθέσιμο (π.χ. αλλαγή από UDP σε TCP).
7. Ελέγξτε αν υπάρχει γνωστό incident/outage στο ISP ή στο VPN gateway.

### Escalation

Αν το πρόβλημα αφορά πολλαπλούς χρήστες ταυτόχρονα, δημιουργήστε αμέσως **major incident** και ενημερώστε την ομάδα δικτύων — μην συνεχίζετε να λύνετε 1-προς-1.

## 3. Εκτυπωτής δεν εκτυπώνει

**Συμπτώματα:** Η εργασία εκτύπωσης "κολλάει" στην ουρά ή δεν φτάνει καθόλου στον εκτυπωτή.

### Βήματα

1. Ελέγξτε αν ο εκτυπωτής είναι online και έχει χαρτί/toner.

2. Στο PC του χρήστη, ανοίξτε την ουρά εκτύπωσης και ακυρώστε τυχόν "κολλημένες" εργασίες.

3. Επανεκκινήστε την υπηρεσία Print Spooler:

```powershell
Restart-Service -Name Spooler -Force
```

4. Επιβεβαιώστε ότι το PC "βλέπει" τον εκτυπωτή στο δίκτυο (ping στο IP του εκτυπωτή).

5. Αφαιρέστε και προσθέστε ξανά τον εκτυπωτή, ή ενημερώστε το driver αν είναι παλιό.

6. Δοκιμάστε εκτύπωση test page απευθείας από τον πίνακα ελέγχου του εκτυπωτή (εξαιρεί hardware βλάβη).

### Escalation

Hardware βλάβη ή error codes στην οθόνη του εκτυπωτή → προωθήστε στον προμηθευτή/service εκτυπωτών.

## 4. Πλήρης δίσκος (Disk full)

**Συμπτώματα:** Ειδοποίηση χαμηλού χώρου, εφαρμογές crash, server δεν γράφει logs.

### Βήματα

1. Επιβεβαιώστε τον διαθέσιμο χώρο:

```bash
df -h
```

2. Εντοπίστε τους μεγαλύτερους φακέλους/αρχεία:

```bash
du -h --max-depth=2 /var | sort -rh | head -20
```

3. Ελέγξτε συνήθεις "ενόχους": log αρχεία, παλιά backups, temp files, core dumps.

4. Καθαρίστε log αρχεία με ασφάλεια (rotate/compress, μην διαγράφετε ενεργά logs χωρίς λόγο):

```bash
journalctl --vacuum-time=7d
```

5. Αν πρόκειται για backup φάκελο, εφαρμόστε το retention policy (δείτε `backup-with-rsync.sh`).

6. Αν ο χώρος δεν επαρκεί μόνιμα, καταγράψτε αίτημα για επέκταση δίσκου/volume.

### Escalation

Production server με disk usage >95% χωρίς άμεση λύση → ειδοποιήστε αμέσως τον υπεύθυνο υποδομών, καθώς κινδυνεύει η διαθεσιμότητα της υπηρεσίας.

## 5. Email δεν παραλαμβάνεται / αποστέλλεται

**Συμπτώματα:** Ο χρήστης δεν λαμβάνει emails ή τα δικά του δεν φτάνουν στον παραλήπτη.

### Βήματα

1. Επιβεβαιώστε ότι το πρόβλημα δεν είναι μεμονωμένο (ρωτήστε αν επηρεάζει και άλλους).
2. Ελέγξτε το μέγεθος του mailbox — αν είναι στο όριο, το email server μπλοκάρει νέα μηνύματα.
3. Ελέγξτε τους φακέλους Junk/Spam και τους κανόνες (rules) του mailbox.
4. Για αποστολή: ζητήστε το ακριβές μήνυμα σφάλματος (NDR/bounce message) και ελέγξτε τον κωδικό σφάλματος.
5. Ελέγξτε αν ο domain/IP αποστολής είναι σε blacklist (π.χ. μέσω mxtoolbox.com).
6. Επιβεβαιώστε ρυθμίσεις SPF/DKIM/DMARC αν το πρόβλημα αφορά απόρριψη από εξωτερικούς παραλήπτες.

### Escalation

Προβλήματα σε επίπεδο mail server (queue stuck, service down) → προωθήστε άμεσα στον διαχειριστή mail συστήματος.

## 6. Server / Service down

**Συμπτώματα:** Μια υπηρεσία δεν αποκρίνεται, χρήστες αναφέρουν "δεν ανοίγει η εφαρμογή".

### Βήματα

1. Επιβεβαιώστε το πρόβλημα independently (μην βασίζεστε μόνο στην αναφορά του χρήστη):

```bash
systemctl status <service-name>
curl -I https://service-url
```

2. Ελέγξτε τα πρόσφατα logs της υπηρεσίας για errors:

```bash
journalctl -u <service-name> --since "15 minutes ago"
```

3. Δοκιμάστε restart της υπηρεσίας:

```bash
systemctl restart <service-name>
```

4. Ελέγξτε χρήση CPU/RAM/δίσκου στον server — μήπως το πρόβλημα είναι πόρων.

5. Επιβεβαιώστε ότι εξαρτημένες υπηρεσίες (database, cache) είναι επίσης up.

6. Αν το restart λύσει προσωρινά το πρόβλημα αλλά επανεμφανίζεται, καταγράψτε το ως recurring issue — μην το κλείνετε ως λυμένο.

### Escalation

Οποιοδήποτε outage επηρεάζει πολλαπλούς χρήστες ή production περιβάλλον → δημιουργήστε **major incident**, ενημερώστε stakeholders άμεσα, και ακολουθήστε τη διαδικασία incident management του οργανισμού.

## 7. Αργή απόδοση σταθμού εργασίας (Slow PC)

**Συμπτώματα:** Ο υπολογιστής "κολλάει", αργεί να ανοίξει εφαρμογές.

### Βήματα

1. Ελέγξτε χρήση CPU/RAM/δίσκου μέσω Task Manager (`Ctrl+Shift+Esc`).
2. Εντοπίστε διεργασίες με ασυνήθιστα υψηλή χρήση πόρων.
3. Ελέγξτε αν τρέχει antivirus scan ή Windows Update στο background.
4. Ελέγξτε διαθέσιμο χώρο στον δίσκο συστήματος (C:) — λιγότερο από 10% ελεύθερο επηρεάζει σοβαρά την απόδοση.
5. Απενεργοποιήστε περιττά προγράμματα εκκίνησης (`Startup apps` στις Ρυθμίσεις).
6. Επανεκκινήστε το σύστημα — απλό αλλά συχνά αποτελεσματικό.
7. Αν το πρόβλημα επιμένει, ελέγξτε για malware με πλήρες scan.

### Escalation

Αν η απόδοση παραμένει χαμηλή μετά από όλα τα παραπάνω, πιθανό hardware ζήτημα (δίσκος, RAM) — προγραμματίστε τεχνικό έλεγχο ή αντικατάσταση εξοπλισμού.
