## 📌 1. Τι είναι το Cloud Computing;

Το **Cloud Computing** είναι η δυναμική παροχή υπολογιστικών πόρων (υπολογιστική ισχύς, αποθηκευτικός χώρος, βάσεις δεδομένων, δίκτυα, λογισμικό) μέσω του Internet, με μοντέλο χρέωσης βάσει χρήσης (**Pay-as-you-go**). 

Αντί μια εταιρεία να αγοράζει, να εγκαθιστά και να συντηρεί φυσικούς servers στο υπόγειό της (On-Premises υποδομή), νοικιάζει τις υποδομές αυτές από μεγάλους παρόχους (Cloud Providers) όπως η **AWS (Amazon Web Services)**, η **Microsoft Azure** και η **Google Cloud Platform (GCP)**.

* **On-Demand Self-Service:** Ο χρήστης μπορεί να δεσμεύσει πόρους (π.χ. έναν νέο server) αυτόματα με μερικά κλικ, χωρίς να χρειάζεται ανθρώπινη παρέμβαση από τον πάροχο.
* **Broad Network Access:** Οι υπηρεσίες είναι προσβάσιμες από οπουδήποτε, μέσω οποιασδήποτε συσκευής με σύνδεση στο Internet.
* **Resource Pooling:** Οι φυσικοί πόροι του παρόχου μοιράζονται δυναμικά σε πολλούς πελάτες (Multi-tenancy), χωρίς ο ένας να επηρεάζει ή να βλέπει τα δεδομένα του άλλου.
* **Rapid Elasticity:** Η υποδομή μπορεί να μεγαλώσει (scale up/out) ή να μικρύνει (scale down/in) ακαριαία, ανάλογα με τη ζήτηση και το traffic.
* **Measured Service:** Η χρήση καταγράφεται με ακρίβεια (π.χ. ανά δευτερόλεπτο ή ανά gigabyte) και ο πελάτης πληρώνει μόνο για ό,τι κατανάλωσε.

## 🏗️ 2. Μοντέλα Υπηρεσιών (Cloud Service Models)

Η κατανομή των ευθυνών μεταξύ του πελάτη και του Cloud παρόχου ορίζεται από το **Shared Responsibility Model** και χωρίζεται σε τρεις βασικές κατηγορίες:

* **Περιγραφή:** Ο πάροχος προσφέρει τα απολύτως βασικά: φυσικό hardware, δικτύωση, storage και virtualization. Ο πελάτης αναλαμβάνει να εγκαταστήσει το Λειτουργικό Σύστημα (OS), τα runtimes και τις εφαρμογές του.
* **Παράδειγμα:** AWS EC2, Azure VMs, Google Compute Engine.
* **Αναλογία:** Νοικιάζεις ένα άδειο οικόπεδο/σπίτι και βάζεις τα δικά σου έπιπλα.

* **Περιγραφή:** Ο πάροχος διαχειρίζεται το hardware, το δίκτυο, αλλά και το Λειτουργικό Σύστημα και τις βάσεις δεδομένων. Ο πελάτης επικεντρώνεται αποκλειστικά στη συγγραφή και το deployment του κώδικά του.
* **Παράδειγμα:** AWS Elastic Beanstalk, Heroku, Google App Engine.
* **Αναλογία:** Νοικιάζεις ένα έτοιμο δωμάτιο σε ξενοδοχείο. Δεν σε νοιάζει η καθαριότητα ή οι υδραυλικές εγκαταστάσεις, απλά μένεις εκεί.

* **Περιγραφή:** Μια πλήρης, έτοιμη εφαρμογή που τρέχει στο Cloud και την οποία ο χρήστης καταναλώνει συνήθως μέσω ενός web browser. Ο πελάτης δεν διαχειρίζεται απολύτως τίποτα στην υποδομή.
* **Παράδειγμα:** Microsoft 365, Google Drive, Gmail, Salesforce.
* **Αναλογία:** Τρως σε ένα εστιατόριο. Δεν σε νοιάζει πώς μαγειρεύτηκε ή πού αγοράστηκαν τα υλικά, απλά καταναλώνεις το φαγητό.

## 🌐 3. Μοντέλα Ανάπτυξης (Cloud Deployment Models)

* **Public Cloud:** Οι υποδομές ανήκουν εξ ολοκλήρου στον Cloud πάροχο και μοιράζονται σε χιλιάδες πελάτες μέσω του δημόσιου Internet. Προσφέρει το μικρότερο κόστος και τη μεγαλύτερη ευελιξία.
* **Private Cloud:** Η υποδομή χρησιμοποιείται αποκλειστικά από έναν οργανισμό. Μπορεί να βρίσκεται στο φυσικό data center της εταιρείας ή να φιλοξενείται από τρίτο πάροχο. Προσφέρει μέγιστη ασφάλεια και έλεγχο.
* **Hybrid Cloud:** Ο συνδυασμός Public και Private Cloud. Τα δεδομένα και οι εφαρμογές επικοινωνούν μεταξύ των δύο κόσμων. Χρησιμοποιείται συχνά από τράπεζες (π.χ. ευαίσθητα δεδομένα πελατών στο Private Cloud, βαριές εφαρμογές analytics στο Public Cloud).

## 🔀 4. Γεφυρώνοντας τα Δίκτυα με το Cloud (On-Premises vs Cloud)

Η μετάβαση από τις παραδοσιακές υποδομές (On-Premises) στο Cloud δεν καταργεί τις αρχές των δικτύων. Αντίθετα, τις υλοποιεί μέσω λογισμικού (**Software-Defined Networking - SDN**).

| Παραδοσιακό Δίκτυο (On-Premises) | Αντίστοιχο στο Cloud (π.χ. AWS) | Περιγραφή |
| :--- | :--- | :--- |
| **Φυσικό Data Center / LAN** | **VPC** (Virtual Private Cloud) | Ένα απομονωμένο, ιδιωτικό εικονικό δίκτυο μέσα στο Cloud. |
| **Subnets (Υποδικτύωση)** | **Public & Private Subnets** | Διαχωρισμός του VPC σε υποδίκτυα με πρόσβαση στο Internet (Public) ή χωρίς (Private). |
| **Router / Gateway** | **Internet Gateway / Route Tables** | Εικονικές συσκευές και πίνακες που καθορίζουν πού δρομολογούνται τα πακέτα. |
| **Firewall / ACLs** | **Security Groups / Network ACLs** | Φίλτρα ασφαλείας που επιτρέπουν ή μπλοκάρουν την κίνηση σε επίπεδο server ή υποδικτύου. |
| **Φυσικός Server** | **EC2 Instance / Virtual Machine** | Ένας εικονικός υπολογιστής που εκτελεί εργασίες. |

## ⚖️ 5. Προχωρημένες Έννοιες Cloud Υποδομών

Στις Cloud αρχιτεκτονικές, η κίνηση δεν οδηγείται ποτέ σε έναν μόνο server. Ο **Load Balancer** δέχεται τα αιτήματα των χρηστών και τα μοιράζει σε μια ομάδα από servers (Server Pool) για την αποφυγή υπερφόρτωσης.
* **Layer 4 Load Balancing:** Λειτουργεί στο Transport Layer. Προωθεί την κίνηση βασιζόμενος αποκλειστικά σε IP και Ports (ταχύτατο, αλλά χωρίς γνώση του περιεχομένου).
* **Layer 7 Load Balancing (Application Load Balancer):** Λειτουργεί στο Application Layer. Μπορεί να διαβάσει HTTP Headers, Cookies και URLs, δρομολογώντας έξυπνα την κίνηση (π.χ. αιτήματα για `/images` πάνε σε specialized storage servers).

Ένα παγκόσμια γεωγραφικά κατανεμημένο δίκτυο από **Edge Servers**. 
* **Σκοπός:** Αποθηκεύει προσωρινά (Caching) στατικό περιεχόμενο (εικόνες, βίντεο, κώδικα HTML/JS) κοντά στην τοποθεσία του χρήστη.
* **Αποτέλεσμα:** Αν ένας χρήστης στην Αθήνα ζητήσει ένα αρχείο από server που βρίσκεται στην Αμερική, το CDN θα του σερβίρει το αρχείο από τον πλησιέστερο Edge Server (π.χ. Φρανκφούρτη ή Αθήνα), μειώνοντας δραματικά το **Latency** (καθυστέρηση).

* **Virtualization (Hypervisor):** Επιτρέπει το σπάσιμο ενός φυσικού server σε πολλά **Virtual Machines (VMs)**. Κάθε VM περιλαμβάνει το δικό του, πλήρες Λειτουργικό Σύστημα (Guest OS), γεγονός που το καθιστά βαρύ σε πόρους.
* **Containers (π.χ. Docker):** Μια πιο σύγχρονη προσέγγιση (Cloud-Native). Τα containers μοιράζονται τον ίδιο πυρήνα (Kernel) του λειτουργικού συστήματος του host. Είναι εξαιρετικά ελαφριά, ξεκινούν σε χιλιοστά του δευτερολέπτου και εξασφαλίζουν ότι μια εφαρμογή τρέχει πανομοιότυπα σε οποιοδήποτε περιβάλλον.

## 🔒 6. Cloud Security

Η ασφάλεια στο Cloud αποτελεί κορυφαία προτεραιότητα και υλοποιείται σε πολλαπλά επίπεδα:

* **Identity and Access Management (IAM):** Κεντρικός έλεγχος πρόσβασης χρηστών και υπηρεσιών. Ορίζει *ποιος* έχει πρόσβαση σε *τι*.
* **Encryption at Rest:** Κρυπτογράφηση των δεδομένων όταν είναι αποθηκευμένα (π.χ. σε δίσκους ή databases).
* **Encryption in Transit:** Κρυπτογράφηση των δεδομένων κατά τη μεταφορά τους μέσα από το δίκτυο (συνήθως μέσω TLS/SSL).
* **Multi-Factor Authentication (MFA):** Πρόσθετο επίπεδο ασφάλειας κατά τη σύνδεση, απαιτώντας δεύτερη μορφή επαλήθευσης (π.χ. κωδικό στο κινητό).

## 📦 7. Cloud Storage Services

Οι πάροχοι Cloud προσφέρουν διαφορετικούς τύπους αποθήκευσης ανάλογα με τη χρήση:

| Τύπος | Περιγραφή | Παράδειγμα (AWS) |
| :--- | :--- | :--- |
| **Object Storage** | Αποθήκευση αρχείων (εικόνες, backups, βίντεο) ως ανεξάρτητα objects. Ιδανικό για τεράστιο όγκο αδόμητων δεδομένων. | **AWS S3** |
| **Block Storage** | Σκληροί δίσκοι υψηλής ταχύτητας που προσαρτώνται άμεσα σε Virtual Machines. Απαραίτητο για Λειτουργικά Συστήματα. | **AWS EBS** |
| **File Storage** | Κοινόχρηστα συστήματα αρχείων (NFS/SMB) που μπορούν να προσπελαστούν ταυτόχρονα από πολλούς servers. | **AWS EFS** |

## ⚙️ 8. Infrastructure as Code (IaC)

Το **IaC** είναι η πρακτική διαχείρισης και provisioning υποδομών (servers, δίκτυα, βάσεις) μέσω κώδικα, καταργώντας τις χειροκίνητες ρυθμίσεις σε web consoles.

* **Εργαλεία:**
  * Terraform (Platform agnostic)
  * AWS CloudFormation (AWS Native)
  * Ansible (Configuration management)
* **Πλεονεκτήματα:**
  * **Αυτοματισμός:** Δημιουργία χιλιάδων πόρων σε δευτερόλεπτα.
  * **Επαναληψιμότητα:** Ακριβές αντίγραφο του περιβάλλοντος (π.χ. από Dev σε Prod).
  * **Version Control:** Ο κώδικας της υποδομής μπαίνει στο Git, επιτρέποντας rollback και συνεργασία ομάδων.

## 🚀 9. Serverless Computing

Το μοντέλο όπου ο προγραμματιστής γράφει μόνο τον κώδικα, χωρίς να ασχολείται καθόλου με τη διαχείριση, το provisioning ή το patching των servers.

* **Παραδείγματα Υπηρεσιών:**
  * AWS Lambda
  * Azure Functions
  * Google Cloud Functions
* **Οφέλη:**
  * **Αυτόματο Scaling:** Από 0 σε 10.000 requests ακαριαία.
  * **Χρέωση ανά εκτέλεση:** Πληρώνεις αποκλειστικά για τα χιλιοστά του δευτερολέπτου (ms) που έτρεξε ο κώδικας.
  * **Μειωμένο λειτουργικό κόστος:** Ο πάροχος αναλαμβάνει το 100% της συντήρησης.

## ☸️ 10. Container Orchestration

Όταν υπάρχουν εκατοντάδες ή χιλιάδες containers (microservices) σε μια υποδομή, απαιτείται ένα σύστημα αυτοματοποιημένης διαχείρισης. Το κορυφαίο εργαλείο για αυτό είναι το **Kubernetes (K8s)**.

* **Κύρια Χαρακτηριστικά (Kubernetes Features):**
  * **Auto Scaling:** Αυξομείωση του αριθμού των containers ανάλογα με την κίνηση.
  * **Self-Healing:** Αν ένα container "κρασάρει", το σύστημα το επανεκκινεί ή το αντικαθιστά αυτόματα.
  * **Load Balancing:** Κατανομή της κίνησης εξίσου μεταξύ των διαθέσιμων containers.
  * **Rolling Updates:** Ενημέρωση της εφαρμογής σε νέα έκδοση χωρίς καθόλου downtime.

## 📊 11. Monitoring & Observability

Η διαρκής παρακολούθηση της απόδοσης, της υγείας και της ασφάλειας των cloud εφαρμογών είναι κρίσιμη για κάθε παραγωγικό σύστημα.

* **Βασικοί Πυλώνες:**
  * **Metrics (Μετρικές):** Αριθμητικά δεδομένα (π.χ. % χρήση CPU, Memory, Network traffic).
  * **Logs (Καταγραφές):** Λεπτομερής καταγραφή συμβάντων, σφαλμάτων και ενεργειών συστήματος.
  * **Tracing (Ιχνηλάτηση):** Παρακολούθηση της διαδρομής ενός αιτήματος (request) μέσα από πολλαπλά microservices για εντοπισμό καθυστερήσεων.
* **Δημοφιλή Εργαλεία:**
  * Prometheus (Για συλλογή μετρικών)
  * Grafana (Για οπτικοποίηση/Dashboards)
  * AWS CloudWatch (Native AWS monitoring)
