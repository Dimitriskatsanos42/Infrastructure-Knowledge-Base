# 9. Ασφάλεια backup: κρυπτογράφηση, immutability, ransomware

### 9.1 Γιατί οι επιτιθέμενοι στοχεύουν τα backups
Οι σύγχρονες επιθέσεις ransomware **πρώτα** εντοπίζουν και διαγράφουν/κρυπτογραφούν τα backups (π.χ. διαγραφή shadow copies, παραβίαση του backup server), και μόνο μετά κρυπτογραφούν τα παραγωγικά δεδομένα. Αν χάσεις και τα backups, μένουν μόνο τα λύτρα.

### 9.2 Βέλτιστες πρακτικές

| Πρακτική | Λεπτομέρειες |
|---|---|
| **Κρυπτογράφηση at-rest** | AES-256 στο backup (Veeam encryption, restic default, BitLocker στους δίσκους) |
| **Κρυπτογράφηση in-transit** | TLS/SSH κατά τη μεταφορά |
| **Immutability** | S3 Object Lock, Veeam Hardened Linux Repository, WORM storage |
| **Air-gap / offline** | Εναλλασσόμενοι δίσκοι ή ταινίες εκτός δικτύου |
| **Διαχωρισμός διαπιστευτηρίων** | Οι λογαριασμοί backup **όχι** domain admin και **όχι** ίδιοι με τα παραγωγικά |
| **Backup server εκτός domain** (ή σε ξεχωριστό management domain) | Αν παραβιαστεί το AD, δεν παραβιάζεται αυτόματα το backup |
| **MFA** | Στην κονσόλα backup και στο cloud storage |
| **Least privilege** | Ο λογαριασμός που **γράφει** backups δεν πρέπει να μπορεί να **διαγράφει** παλαιά |
| **Δίκτυο** | Ξεχωριστό VLAN για backup traffic και storage |
| **Παρακολούθηση (monitoring)** | Alerts για αποτυχημένα jobs, ασυνήθιστη διαγραφή backups |
| **Ενημερώσεις** | Patching του backup server (ήταν στόχος κρίσιμων ευπαθειών) |
| **Αποθήκευση κλειδιών** | Αποθήκευση των κλειδιών/κωδικών κρυπτογράφησης **εκτός** του συστήματος που προστατεύεις |
| **Έλεγχος ακεραιότητας** | Checksums, `restic check`, SureBackup, scheduled test restores |

> ⚠️ **Κρίσιμο:** Αν χάσεις το κλειδί/κωδικό κρυπτογράφησης, τα backups είναι **μη ανακτήσιμα**. Φύλαξε αντίγραφο σε ασφαλές μέρος (password manager + εκτυπωμένο σε χρηματοκιβώτιο).

### 9.3 Ανάκτηση από ransomware – σύντομο playbook

1. **Απομόνωσε** τα προσβεβλημένα συστήματα (αποσύνδεση από δίκτυο, όχι σβήσιμο, για forensic).
2. **Μην πληρώσεις αμέσως**· ενημέρωσε διοίκηση, νομικό τμήμα, CERT/αρχές.
3. **Προσδιόρισε** τον τρόπο εισόδου και το χρονικό σημείο προσβολής.
4. **Επιβεβαίωσε** ότι τα backups **δεν** είναι μολυσμένα (restore σε απομονωμένο περιβάλλον, antivirus scan – Veeam Secure Restore).
5. **Καθάρισε / ξαναστήσε** συστήματα και αλλαγή **όλων** των κωδικών και κλειδιών.
6. **Επανάφερε** πρώτα τις κρίσιμες υπηρεσίες (AD, DNS, DHCP → εφαρμογές).
7. **Ενίσχυσε** την ασφάλεια και ξαναδοκίμασε τα backups.
8. **Post-mortem**: καταγραφή μαθημάτων.
